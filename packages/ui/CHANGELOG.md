# Changelog

## 4.6.0

### Minor Changes

- 0219812: AI agents get one canonical entry point. `llms.txt` opens with a recipe for every screen type (app shell, list, form, settings, auth, dashboard, landing, theming), then decision tables and a "common workarounds" page; `get_guide` and the new per-page files `/llms/<slug>.txt` carry the complete demo source of each page, while `llms-full.txt` stays under its old size. `ca-ui-mcp` adds `get_recipe` and reports deprecated components (`Row`, `GlassCard`, `GlassSurface`) with their replacement. `init` writes a marked, idempotent block into the app's `AGENTS.md`. The agent skill no longer teaches the removed `cols`/pixel-`gap` layout API or deprecated components.
- 1b1b993: `AspectRatio` (#446, part of #432): a box that holds `ratio` for a video, an embed or any child with no size of its own; a direct `img`, `video`, `iframe`, `canvas` or `svg` child fills it. `Image` gains `ratio` (crop to a width / height box, filling the container) and `fit` (`cover` or `contain`). Replaces the Radix `AspectRatio` row of the React equivalence table.
- 23fa9ee: Auth building blocks (#379): `Turnstile` in `@codeatlasdev/ui/forms` (Cloudflare captcha, explicit render, loads the vendor script on demand with no dependency and no server access, follows the colour scheme and the locale, `bind:handle` with `getToken()` / `reset()`, removed on unmount, silent no-op without a `siteKey`), `PasswordStrength` (3-step meter with a polite text label, pure `passwordScore()` and a `score` / `labels` override), `SplashScreen` (`role="status"`, `ready` + `minDuration`, skipped under reduced motion) and `Avatar` `decorative` (no accessible name next to a visible name). New i18n groups `passwordStrength`, `splashScreen` and `turnstile` (en, pt-BR).
- 00757fe: `AuthLayout`: `panelTone` (`auto` | `brand` | `flat`) and the `--ca-auth-panel-bg` / `--ca-auth-panel-fg` tokens. A flat panel is a solid surface with a hairline, themed text and no blobs; the default `auto` picks it under the `flat` and `outlined` surface styles, so themes that forbid gradients no longer override `.ca-auth__panel` and `.ca-auth__blobs` from app CSS (#409). The panel slot's `--panel-*` variables are now CSS (derived from `--ca-auth-panel-fg`) instead of an inline style.
- 78ddb7f: `AuthLayout`: `panelSide` (`left`/`right`), `panelBleed` (full-bleed, sticky panel with no padding, logo or blobs, and a hairline divider), `panelHidden` (`md` 900px or `lg` 1200px; the panel snippet is unmounted while hidden, so media inside is never fetched on mobile), a `header` snippet (sticky bar over the form column that replaces the mobile brand strip) and `align="start"`. `AuthCard` gets `variant="plain"` (display-size title, no card width cap). New template: Waitlist with map (#347).
- b192b0a: `Badge` renders an inline status pill: `<Badge tone="danger" subtle dot size="md">Overdue</Badge>` (tones `brand`, `success`, `danger`, `warning`, `info`, `neutral`; `subtle` is a tinted background whose label clears 4.5:1 in light and dark). `Button` gains `trailingHint` (a `Kbd` in `trailing` is hidden below `md` and on touch with no reserved gap) and `align="between"` (label at the start, `trailing` at the end; the spinner keeps its place). Defaults are unchanged.
- acdf4f3: `ButtonGroup` (#448, part of #432): attaches `Button`, `IconButton` and a `DropdownMenu` trigger into one `role="group"` control, horizontal or vertical (`orientation`), with square inner corners, a single-line seam and the hovered or keyboard-focused member raised over it. Replaces the shadcn Button Group row in the React equivalents table.
- 8c31f6a: `Button` and `IconButton` get `tone="neutral"` (#357): `outlined` and `ghost` buttons drawn with a neutral label, border and hover/pressed fills instead of the brand colour, for secondary actions beside a brand `filled` one. `IconButton` also gets the `outlined` variant. Label and border contrast is checked for every preset in `tests/contrast.test.ts`.
- 61912be: `Carousel` and `CarouselItem` (#445, part of #432): native scroll-snap slides that follow the WAI-ARIA carousel pattern (labelled region, slides named "n of m", off-screen slides `inert`, labelled dot buttons with `aria-current`, arrows / Home / End on the focused carousel). `perView`, `loop`, `bind:index`, `onchange`; `autoplay` (ms) is opt in, adds a Pause button, stops on focus or hover, is a polite live region only when stopped, and never runs under `prefers-reduced-motion`. No carousel engine dependency. Replaces shadcn `Carousel`. New i18n group `carousel` (en, pt-BR).
- 82edb9d: `ca-ui-mcp` gains `get_release(version)`: a release as a post for agents, with its highlights, the numbers and the conditions each was measured under, the behaviour changes to check after upgrading, the upgrade command and every merged change grouped by area with its pull request and issue. Without a version it returns the digest of every release. It reads `dist/releases.json`, built from the release posts in the docs site.
- 7b30608: New `ChipGroup`: single choice among a few short options as chips that wrap (#355). A real `radiogroup` of native radios (roving tab stop, arrows/Home/End/Space/Enter, disabled items skipped), three columns below `sm` and free wrap from `sm`, a check icon on the selected chip, `error` as `role="alert"` with `aria-invalid`/`aria-describedby` on the group, `name`/`required` for native forms, 44px chips. Use it instead of `RadioGroup` (too tall) or `SegmentedControl` (never wraps) for options like team size.
- 689d2c5: New token `--ca-code-line-height` (20px): an integer px line height for code surfaces. `CodeSnippet`, `.ca-code pre` and a bare Markdown `pre` inside `.ca-prose` use it instead of the unitless 1.6 / 1.7, which rounded to a different pixel height in a text layer and in an overlay (a caret and an active-line highlight drifting apart). The `code` inside a `CodeSnippet` also pins `--ca-font-mono` now: it used the UA's bare `monospace`, resolved per lookup. The docs gain "Code surfaces: integer line-height, one font stack" for apps that build an editor.
  
  The stylesheet also drops `--ca-action-focus`, a token no component, doc or template ever read, to stay inside its size budget.
- caf82ad: Component tokens for `Button`, `IconButton` and `Kbd`. Weight, tracking, line-height, gap, per-size padding, height and font size, ghost border width, disabled background and the touch minimum are `--ca-btn-*`, `--ca-icon-btn-*` and `--ca-kbd-*` custom properties; set them on `:root`, on a wrapper or through the new `ThemeOptions.components` (`button`, `iconButton`, `kbd`, merged by `mergeTheme`). Unset, every component draws exactly what it drew in 4.5.0. One naming convention for all components (`--ca-<component>-<property>`, `--ca-<component>-<size>-<property>`) is documented in the theming guide. No more selectors against `.ca-btn--lg`, `.ca-icon-btn` or `.ca-kbd`.
- 3b76318: `ca-ui-mcp` gains `list_concepts` and `get_concept`: the Concepts pages (viewport-complete UX, motion that respects people, targets and focus, appeal is not usability) with every claim's strength label, scope, sources, limits and last-reviewed date. The llms-full concept digest now carries the contract and the prompt only, so the file stays under its size cap.
- e125cc8: `ContextMenu` (#455): wraps a region and opens a `DropdownMenu` at the pointer on right-click (a second one moves it), at the finger on a touch long-press (`longPressDelay`, default 500 ms, cancelled by lifting early or dragging) and from the keyboard with Shift+F10 or the ContextMenu key. The `menu` snippet takes the same items as `DropdownMenu` (items, checkbox and radio items, submenus, labels, separators). Text fields keep the browser's menu; `disabled` keeps it everywhere; `bind:open`, `onOpenChange`, `focusable`, `menuClass`.
- c19ba2b: Density and appearance tokens for `Avatar`, `TextArea`, `TextField`, `Card`, `SegmentedControl` and `EmptyState`, on the same `--ca-<component>-<property>` convention as the Button tokens, also settable through `ThemeOptions.components`. `Avatar` gets `tone="neutral"` (surface background, secondary text, hairline ring) and `--ca-avatar-fallback-{bg,color,size,weight}` with per-size `--ca-avatar-<size>-fallback-*`. `TextField` and `TextArea` read `--ca-field-gap` and `--ca-field-label-leading` (or their own `--ca-tf-*` and `--ca-ta-*`); `--ca-ta-min-height` is the height of the visible box, border included. `Card` reads `--ca-card-{bg,radius,border,shadow}`. `SegmentedControl` reads `--ca-seg-item-{padding-x,font-size,line-height}` (and per size). `EmptyState` gets `bare`, `actionsFill` and `--ca-empty-{padding,title-size,title-weight}`. Unset, every component draws what it drew in 4.5.0.
- ab42958: `ca-ui-mcp` gains `search_terms`, `get_term` and `get_reference`: the 269-term design atlas and the verified sources behind it, offline from `dist/atlas.json`. Scores are labelled heuristic, every term carries its limits and review date, and a reference returns what it does not support and the wording that was read.
- 73f38cd: Design style pages (#583): `/styles/<id>/` for `swiss`, `editorial`, `brutalism`, `sketchbook`, `glassmorphism` and `terminal`, each rendered in its own style, with the origin, the traits (type, colour, shape, depth, motion), do and don't, accessibility pitfalls with their sources, before and after on real components, the `designStyle()` recipe and a prompt. The `ca-ui-mcp` server gains `get_style` (a style as markdown, or the digest of all of them) and `llms.txt` links the digest at `/llms/styles.txt`. `designDefaults()` is exported: the stylesheet default of every knob a theme can write, so a scoped preview can reset what an outer theme set.
- 300ac7c: `Dialog` split is configurable: `splitSize={{ width, height }}` (any CSS length), `splitColumns="2fr 3fr"` and `fullscreenBelow="sm" | "md"` (any size: exactly the viewport under the breakpoint, square corners, safe-area padding kept). They set the tokens `--ca-dialog-split-width`, `--ca-dialog-split-height` and `--ca-dialog-split-columns`. Defaults are unchanged. The insertion-line-free column drop requested in the same issue already ships as `sortable({ drop: 'container' })`; it now has a test for the announced target container on keyboard and touch.
- ca5cc0e: Display text role (#350). New `Heading` component (`level`, `size="display" | "display-2" | "display-3" | "h1".."h6"`) bound to `--ca-font-display` (the body font until `fonts.display` is set), the new `--ca-display-tracking` / `--ca-display-leading` tokens and the fluid `--ca-font-size-display-*` sizes. `AuthCard`, `PageShell`, `EmptyState` and `SiteHeader` take a `display` prop. `defineTheme({ typography: { displayTracking, displayLeading } })` sets the tokens.
- e5c7c0f: `DocsHeader` is the top bar of `DocsShell` as its own component, so the pages of a site that are not a docs frame (a landing page, a template gallery) render the same header as the docs: one height, container width, brand position, section tabs with an underline for the current one, search (⌘K), actions and theme toggle, and the same phone menu. The bar is now opaque (it was an 82% translucent fill with a blur), so content scrolled under it no longer shows through.
- 4e4bd67: `Drawer` gets `chromeless` and `fullBleedBelow` (#362), mirroring `Dialog`'s `chromeless`. `chromeless` renders no header, close button or footer actions and no body padding, so a detail view can bring its own header and scroll area; the panel is still named by `title` (screen readers only), `aria-label` or `aria-labelledby`. `fullBleedBelow="sm" | "md" | "lg"` makes a left/right panel exactly the viewport width and `--ca-vh` height below that breakpoint (no radius, border or page strip, safe-area padding kept). `.ca-drawer__body` is now a flex column with `min-height: 0`, so a child can own the scroll.
- 2cc7983: Editorial primitives (#353). New tokens `--ca-font-size-display-hero` (fluid, 60-216px) and `--ca-ease-out-expo` / `--ca-ease-out-quart` / `--ca-ease-in-out-quart` (also in the `easing` export). New `Highlight` and `StrikeThrough` components with `animated`, drawn in their final state under `prefers-reduced-motion`. `Surface` takes `grain` (`true | "animated"`), a paper-noise overlay tuned by `--ca-grain-opacity` / `--ca-grain-size`. Fix: `--ca-font-mono` (and `fontFamily.mono`) now starts with the system monospace instead of JetBrains Mono, which the kit does not load; set `fonts.mono` to pick another.
- 446c722: `HoverCard` (#454): a rich preview that opens on pointer hover (after `openDelay`) and on keyboard focus (at once), stays open while the pointer crosses into it (`closeDelay`), closes on Escape and blur, and is reachable with Tab from the trigger. A hint layer: it never takes Escape or presses from the layer below. Touch never opens it, so a tap only runs the trigger's own action (use `Popover` for a tap-to-open preview). `triggerChild`/`trigger`, `bind:open`, `onOpenChange`, `side`, `align`, `sideOffset`. `FloatingLayer` forwards `onfocusout`.

- a5bc3b7: `init --write` now produces a SvelteKit app that passes `vite build`, `svelte-check --fail-on-warnings` and `codeatlas-ui lint` as written, on Kit 2 and Kit 3.
  
  - **PWA and SEO are opt-in.** The manifest route, service worker, offline page, `robots.txt` and `sitemap.xml` are written only with `init --with pwa` (also combinable: `--with lint,e2e,pwa`). A plain `init` writes no `manifest` link in `<Seo>` (the old default failed the prerender with a 404 as soon as the manifest route was removed). `--with pwa` can be added later to an app `init` already set up.
  - **Lint-clean output.** The copy `init` writes (layout title, offline page, manifest name) lives in `src/lib/messages.ts` (`export const m`), so `codeatlas-ui lint` no longer reports `i18n-literal` on a freshly initialised app.
  - **Kit 3 `#lib/*` map.** `init` adds `"imports": { "#lib/*": "./src/lib/*" }` to `package.json` (never replacing an existing map) and imports the theme and messages through it, instead of relative paths.
  - **Missing config files are created**: `vite.config.ts`, `src/app.html` (without the inline-styled `display: contents` wrapper) and `tsconfig.json` instead of `skip ... (not found)`. Kit 2's `tsconfig.json` gets `allowImportingTsExtensions`, `noEmit` and `skipLibCheck`, which its generated base config lacks; an existing file only gains the options it does not set.
  - **`@sveltejs/adapter-static`**: the adapter output folder (`build`, or the `pages` option) goes into the tsconfig `exclude`, so `svelte-check` no longer scans it, and `src/routes/+layout.ts` gets `export const prerender = true;`. `init` notes when the adapter major does not pair with the Kit major (`@sveltejs/adapter-static@4` for Kit 3, `@3` for Kit 2).
  - **`prerender.handleUnseenRoutes: "ignore"`** is written into the `vite.config.ts` that `--with pwa` creates on Kit 3 (no page links to `/robots.txt` or `/sitemap.xml`), and noted otherwise.
  - **Fixed the public-origin note.** Kit 2 rejects `kit.paths.origin`; the mechanism is `kit.prerender.origin` there and `sveltekit({ paths: { origin } })` on Kit 3.
  - A re-run no longer mistakes the theme import `init` wrote into `vite.config.ts` for an app-owned theme.
