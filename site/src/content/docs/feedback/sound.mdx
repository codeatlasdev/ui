Sound lives in its own entry, `@codeatlasdev/ui/sound`, so the core stays silent and weightless. Components only announce what happened through a no-op `soundBus`; importing the entry registers the one listener that turns those announcements into short synthesized cues. There are no audio files: every cue is a few oscillators, a noise burst and an envelope, built when it plays. The whole entry (engine, four profiles, the `use:sound` action and `SoundToggle`) is under 4 KB gzip.

```svelte
<script>
  import { Button, Switch } from "@codeatlasdev/ui";
  import { SoundToggle } from "@codeatlasdev/ui/sound";
  let on = $state(false);
</script>

<SoundToggle />                      <!-- off by default; the choice is saved in localStorage -->
<Button sound>Save</Button>          <!-- press and release -->
<Switch sound bind:checked={on} />   <!-- toggle-on / toggle-off -->
```

Nothing plays until the user presses `SoundToggle`, and even then the browser's audio context is only created inside their next pointer or key event. Read the [principles](/docs/getting-started/sound-principles/) before adding sound to a screen.

## Profiles

A profile is a handful of numbers (waveform, root pitch, cue length, filter, noise share, gain), not a set of recordings. The profile follows the active design style, so a brutalist theme clicks and a glass theme chimes with no extra setup.

| Profile | Design style | Character |
|---|---|---|
| `system` | default, material, swiss, ... | neutral, short, low-gain sine blips |
| `glass` | `glassmorphism`, `liquid` | soft sine chimes with a high shimmer and a short tail |
| `brutal` | `brutalism` | dry square-wave and noise clicks, hard stops |
| `terminal` | `terminal` | square-wave beeps and keyboard-like ticks |

`designStyle("brutalism")` writes `--ca-sound-profile: brutal` on `:root`, and the engine reads it per cue. Without it the engine falls back to the surface material (`<html data-style>`), then to `system`. Pin one yourself with `sound.use(profile)` (and `sound.use(undefined)` to follow the style again).

Tune a profile from CSS, read once per cue:

| Token | Effect |
|---|---|
| `--ca-sound-profile` | which profile plays (`system`, `glass`, `brutal`, `terminal`) |
| `--ca-sound-gain` | multiplies the profile level, default `1` |
| `--ca-sound-pitch` | multiplies the root pitch, default `1` |
| `--ca-sound-brightness` | multiplies the filter cutoff, default `1` |

## On components

Every component takes the same prop. `sound` is `true` for the component's own cue, or a cue name to play that cue instead. Without the sound entry the prop does nothing.

For any other element use the action: `<div use:sound={{ on: "pointerenter", cue: "hover" }}>`. `hover` only plays in profiles that opt in (`glass`) and never under reduced motion.
