Settings screens are mostly editable lists: pipeline stages, loss reasons, tags, quick replies. Each row is a small form plus a way to reorder and a delete button. `SortableList` owns the reordering and `EditableRow` owns the row layout; the fields are the components you already use.

## Reordering

Every row has a grip (a button, so it is reachable and named: "Move Novo") and a "Reorder" menu with Move up, Move down, Move to the top and Move to the bottom. The menu is the path that needs no drag, for touch and screen readers, and announces the result. A pointer drags from the grip only, so the fields inside a row stay editable, and a touch on the grip starts the drag at once, with no hold. `onreorder({ id, from, to })` reports the move; the list never reorders `items` itself, so you can persist first and put the old order back on failure (the demo does, optimistically).

## EditableRow

The row measures its own width, not the viewport's, so it stacks inside a narrow column on a wide screen too. From 36rem it lays summary, fields and actions on one line, the fields in an auto-fit grid (`--ca-field-min`, default 10rem); below that the summary and actions stay on one line and the fields open under an Edit button (`bind:open` to control it). Give the row a `label` for that button.

## Recipe: a settings page with an editable list

A CRM settings screen: `AppSettings` tabs, one of them an editable list of pipeline stages (grip, reorder menu, delete; on a phone each row collapses to its name with an Edit button), another a list of switches. The side navigation becomes a strip under 900px, so the page needs nothing else for 390px. Copy it whole and change the data and the copy; save through your own endpoint.

```ts
// src/lib/messages.ts (the keys the settings page reads)
export const m = {
  settings: {
    title: "CRM settings",
    description: "Pipeline stages and notifications.",
    save: "Save changes",
    saved: "Settings saved",
    failed: "Could not save the settings",
    tabs: { pipeline: "Pipeline", notifications: "Notifications" },
    stages: {
      title: "Stages",
      description: "Order the stages the way deals move through them.",
      list: "Pipeline stages",
      name: "Name",
      add: "Add stage",
      newName: "New stage",
    },
    email: {
      title: "Email",
      newDeal: "New deal assigned",
      newDealHint: "One email per assignment.",
      digest: "Weekly digest",
      digestHint: "A summary every Monday.",
    },
    remove: (name: string) => `Delete ${name}`,
  },
} as const;
```

```svelte
<!-- src/routes/(app)/settings/+page.svelte -->
<script lang="ts">
  import { Bell, GitBranch, Plus, Trash2 } from "@lucide/svelte";
  import {
    AppSettings, Button, Divider, EditableRow, FormSection, IconButton, SettingItem, SortableList, Switch, TextField,
    toast, type SortableListReorder,
  } from "@codeatlasdev/ui";
  import { m } from "#lib/messages.ts";

  const tabs = [
    { value: "pipeline", label: m.settings.tabs.pipeline, icon: GitBranch },
    { value: "notifications", label: m.settings.tabs.notifications, icon: Bell },
  ];

  type Stage = { id: string; name: string };
  let stages = $state<Stage[]>([]);
  let emailNewDeal = $state(true);
  let emailDigest = $state(false);
  let saving = $state(false);

  // The list never reorders `items` itself: apply the move to your data.
  function reorder({ from, to }: SortableListReorder) {
    const next = [...stages];
    const [moved] = next.splice(from, 1);
    next.splice(to, 0, moved);
    stages = next;
  }
  const add = () => (stages = [...stages, { id: crypto.randomUUID(), name: m.settings.stages.newName }]);

  async function save() {
    saving = true;
    try {
      const res = await fetch("/api/settings", {
        method: "PUT",
        headers: { "content-type": "application/json" },
        body: JSON.stringify({ stages, emailNewDeal, emailDigest }),
      });
      if (res.ok) toast.success(m.settings.saved);
      else toast.error(m.settings.failed);
    } finally {
      saving = false;
    }
  }
</script>

<AppSettings title={m.settings.title} description={m.settings.description} {tabs}>
  {#snippet actions()}
    <Button variant="filled" size="sm" loading={saving} onclick={save}>{m.settings.save}</Button>
  {/snippet}

  {#snippet children(tab)}
    {#if tab === "pipeline"}
      <FormSection title={m.settings.stages.title} description={m.settings.stages.description} layout="stack">
        <SortableList items={stages} getId={(s) => s.id} getLabel={(s) => s.name} onreorder={reorder} label={m.settings.stages.list}>
          {#snippet item(stage)}
            <EditableRow label={stage.name}>
              {#snippet summary()}<strong>{stage.name}</strong>{/snippet}
              <TextField label={m.settings.stages.name} bind:value={stage.name} />
              <Button variant="ghost" size="sm" onclick={() => (stages = stages.filter((s) => s.id !== stage.id))}>
                {#snippet leading()}<Trash2 size={14} />{/snippet}
                {m.settings.remove(stage.name)}
              </Button>
            </EditableRow>
          {/snippet}
        </SortableList>
        <Button variant="outlined" size="sm" onclick={add}>
          {#snippet leading()}<Plus size={14} />{/snippet}
          {m.settings.stages.add}
        </Button>
      </FormSection>
    {:else}
      <FormSection title={m.settings.email.title} layout="list">
        <SettingItem label={m.settings.email.newDeal} description={m.settings.email.newDealHint}>
          <Switch bind:checked={emailNewDeal} />
        </SettingItem>
        <Divider />
        <SettingItem label={m.settings.email.digest} description={m.settings.email.digestHint}>
          <Switch bind:checked={emailDigest} />
        </SettingItem>
      </FormSection>
    {/if}
  {/snippet}
</AppSettings>
```
