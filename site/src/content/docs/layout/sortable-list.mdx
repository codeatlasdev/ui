Settings screens are mostly editable lists: pipeline stages, loss reasons, tags, quick replies. Each row is a small form plus a way to reorder and a delete button. `SortableList` owns the reordering and `EditableRow` owns the row layout; the fields are the components you already use.

<Demo title="Pipeline stages editor" description="Drag the grip, lift a row with Space and move it with the arrows, or use the menu on the row. Narrow the window below 36rem of row width and each row collapses to its name with an Edit button." src={StagesSrc}><Stages client:visible /></Demo>

## Reordering

Every row has a grip (a button, so it is reachable and named: "Move Novo") and a "Reorder" menu with Move up, Move down, Move to the top and Move to the bottom. The menu is the path that needs no drag, for touch and screen readers, and announces the result. A pointer drags from the grip only, so the fields inside a row stay editable, and a touch on the grip starts the drag at once, with no hold. `onreorder({ id, from, to })` reports the move; the list never reorders `items` itself, so you can persist first and put the old order back on failure (the demo does, optimistically).

## EditableRow

The row measures its own width, not the viewport's, so it stacks inside a narrow column on a wide screen too. From 36rem it lays summary, fields and actions on one line, the fields in an auto-fit grid (`--ca-field-min`, default 10rem); below that the summary and actions stay on one line and the fields open under an Edit button (`bind:open` to control it). Give the row a `label` for that button.
