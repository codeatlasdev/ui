```svelte
<script lang="ts">
  import { AppShellLayout, SiteHeader, type NavModule } from "@codeatlasdev/ui";
  import { goto } from "$app/navigation"; // or any router
  import { page } from "$app/state";

  let { children } = $props();

  const modules: NavModule[] = [/* id, label, icon, basePath, items */];
</script>

<AppShellLayout {modules} pathname={page.url.pathname} onNavigate={(path) => goto(path)}>
  {#snippet header()}<SiteHeader />{/snippet}
  {@render children()}
</AppShellLayout>
```

The shell never imports a router. You pass the current `pathname` and handle `onNavigate`, so it works with SvelteKit, Astro, or plain state. `onNavigate` fires when the user switches module from the rail or the bottom navigation. Panel items are plain `<a href>` links, so a client-side router takes them over like any other link. Put it only on application routes, never on marketing pages. The panel is skipped for a module with fewer than two destinations, since it would only repeat the rail icon and the page title. Below 900px the rail and panel disappear and the mobile header plus bottom navigation take over. See the [templates](/templates/) for complete applications built on it.

The rail magnifies the module icon under the pointer, like a dock. Only the glyph grows, never the button, so the hover background cannot cover the active neighbour. The effect follows the motion scale: it is off with `motion: { scale: 0 }` in the theme and under `prefers-reduced-motion`.

## Panel width

The panel is 200px by default. For lists with long names pass `panelWidth` (px, held between 160 and 480): the content offset and the open and close animation follow it, so the page never misaligns. Add `resizablePanel` to let people choose: a handle sits on the panel's trailing edge and is a keyboard-operable separator (`role="separator"` with `aria-valuenow`, `aria-valuemin` and `aria-valuemax`). Arrow keys move it by 8px, Shift by 32px, Home and End jump to the bounds. While the pointer holds the edge the panel follows it with no spring in between. With `persistPanel` the width is stored with the open state and restored before the first paint; `panelWidth` is the width used until the user picks one. A stored width is ignored when `resizablePanel` is off, so the prop stays the contract.

## Rich panel items

A `NavItem` takes more than an icon and a label:

| Field | What it does |
|---|---|
| `color` | A decorative dot before the label, any CSS color. The icon stays. |
| `leading` | A snippet that replaces the icon (a color swatch, an avatar, an emoji). Decorative: the label is the name. |
| `count` | A neutral total after the label (`1.2k` above 999). The link's name carries the exact number, never "unread". `0` renders. |
| `badge` | Unread-style count: announced "N unread", capped at 99+. Use `count` for a plain total. |
| `actions` | A snippet of `DropdownMenuItem`s. The row gets a "…" button named `Actions for <label>`, a sibling of the link, shown on hover and focus. Needs `itemMenu={NavItemMenu}` on the shell. |

Reordering is per list: set `onReorder` on a `NavSection` (or on the `NavModule` for the items that sit outside any section) and pass `reorder={NavReorder}` to `AppShellLayout`. Each row gets a grip that works with the mouse, touch (press and hold) and the keyboard (Space lifts, arrows move, Enter drops, Escape cancels), and every step is announced. It is the same `useDnd` engine as [drag and drop](/docs/foundation/drag-and-drop/). The shell never reorders `items` for you: commit the move in your state and the new order flows back in. `onReorder` is not called when the drop lands where it started.

`NavReorder` and `NavItemMenu` are opt-in on purpose: the drag engine and the dropdown menu are only bundled by apps that import them, so a shell without per-item menus or reordering stays small.

```svelte
<script lang="ts">
  import { AppShellLayout, DropdownMenuItem, NavItemMenu, NavReorder, type NavModule, type NavReorderEvent } from "@codeatlasdev/ui";

  type Row = { id: string; name: string; color: string; count: number };
  let rows = $state<Row[]>([]);
  function archive() {}

  function reorder(e: NavReorderEvent) {
    const next = rows.slice();
    next.splice(e.to, 0, ...next.splice(e.from, 1));
    rows = next;
  }
</script>

{#snippet menu()}
  <DropdownMenuItem onclick={archive}>{#snippet children()}Archive{/snippet}</DropdownMenuItem>
{/snippet}

<!-- items: rows.map((r) => ({ id: r.id, label: r.name, icon: Folder, path: `/p/${r.id}`, color: r.color, count: r.count, actions: menu })) -->
<!-- <AppShellLayout {modules} {pathname} reorder={NavReorder} itemMenu={NavItemMenu}> -->
```

## State across page loads

On a multi-page site (Astro, a full reload) every link loads a new document, so a shell that only keeps state in memory reopens at its defaults: the panel, the module, the expanded groups and the panel scroll are all lost. With `persistPanel` (the default) the shell keeps them and puts them back before the first paint, the same way the theme script does.

| What | Where | Key |
|---|---|---|
| Panel open or closed, selected module, dragged panel width, section open map | `localStorage` | `ca-shell` |
| Panel scroll, per module | `sessionStorage` | `ca-shell-scroll` |

An inline script emitted right after the sidebar reads those keys and sets `data-ca-panel="open|closed"` and `data-ca-module="<id>"` on `<html>` before anything paints, so a panel the user closed is laid out closed from the first frame instead of flashing open. Stored values are validated and discarded when malformed. A section's last open or closed choice wins over `defaultOpen`, but the section that holds the current page always opens. The module comes from the URL when `modules` matches it, and from the stored choice otherwise.

Render the shell on the server so the first paint is not blank: the inline script and the markup travel together. A client-only mount gets the same restore on hydration, and a page whose CSP blocks inline scripts too. Keep `id` stable on each `NavModule` (it is the stored module key) and each section `label` unique within a module (it is the stored section key).

## Building blocks for a custom panel

`AppShellLayout` renders the panel for you. `Rail`, `Panel`, `BottomNav` and `MobileHeader` are exported too, and two of them are the pieces to reuse when you lay out your own navigation: `PanelNavItem` is the row the panel draws for one `NavItem` (icon or `leading`, `color` dot, label, `count`, unread badge, new dot, the `actions` menu and the active pip), and `SectionGroup` is a titled group of items that collapses.

```svelte
<script lang="ts">
  import { PanelNavItem, SectionGroup, type NavSection } from "@codeatlasdev/ui";

  const section: NavSection = { label: "Reports", collapsible: true, items };
</script>

<SectionGroup {section} {pathname} />
<PanelNavItem item={items[0]} isActive={pathname === items[0].path} href={items[0].path} />
```

`PanelNavItem` renders a row with a plain `<a>` inside it (`aria-current="page"` when active); the actions button and the grip are siblings of the link, because a link cannot contain controls. `SectionGroup` opens itself when it holds the current page, and inside an `AppShellLayout` with `persistPanel` it stores its open state under the section `label`; a bare `SectionGroup` keeps nothing.
