Use `Stat` for a plain number inside a card, a panel or a flex/grid row. It has no background, border or padding and inherits its colour from the container, so it never nests a second box. Use [KpiCard](/docs/layout/kpi-card/) when the metric needs its own card: a `KpiCard` is a `Stat` inside a [Card](/docs/surfaces/card/), so both share one set of typography tokens.

It renders a description list (`<dl>`): the label is the `<dt>`, the value the `<dd>`, so assistive tech reads the label as the name of the number. The label is one line and truncates with an ellipsis in a narrow container (390px); the value uses tabular numerals and never wraps. Text colours are `--ca-text-secondary` (label), `--ca-text-primary` (value) and `--ca-text-hint` (hint). Place several Stats side by side with a grid or flex wrapper; do not wrap each one in a Card.

`trend` is a relative percent change that you compute: `trend={12.5}` shows `+12.5%`. A metric that went from 80 to 90 passes `trend={12.5}`, not `10`.

A trend is good news when it goes up by default: a rise is green, a fall red. For a metric where down is good (churn, cost, latency) set `trendTone="positive-down"`: the arrow still follows the sign, the colour flips, and the accessible label says "better" or "worse" (`Trend: -1.8%, better`; `Tendência: -1.8%, melhor` in pt-BR). `trendTone="neutral"` shows the change without judging it. A zero change is always neutral. Do not drop `trend` and write the delta in `hint` to avoid a wrong colour.
