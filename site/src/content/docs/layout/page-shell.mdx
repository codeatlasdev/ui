```svelte
<script>
  import { PageShell, Button } from "@codeatlasdev/ui";
</script>

<PageShell title="Dashboard" description="Overview of this month">
  {#snippet actions()}<Button size="sm">New report</Button>{/snippet}
  <!-- page content -->
</PageShell>
```

`PageShell` never renders `<main>`. Inside `AppShellLayout` the shell is the `<main id="main">` landmark; on a page with no shell (a one-screen app) wrap it yourself, with a skip link first, or axe reports `landmark-one-main`:

```svelte
<script>
  import { PageShell, SkipLink } from "@codeatlasdev/ui";
</script>

<SkipLink />
<main id="main" tabindex="-1">
  <PageShell title="Pipeline">…</PageShell>
</main>
```

Inside `AppShellLayout` the full-width content region is the scroll container and `PageShell` is only the centred column, so the scrollbar sits at the window edge. Outside a shell `PageShell` scrolls itself.

A one-page app does not need `AppShellLayout` for this. See the [Standalone page](/docs/getting-started/recipes/#standalone-page) recipe.

Below 900px the header stacks: the description leads and `actions` wrap onto their own row. `Button`s share that row full-width (large tap targets); everything else (`IconButton`, `ThemeToggle`, `StatusChip`, `Chip`, `Badge`, plain text) keeps its natural size and stays at the end of the row.

The shell renders `title` as the page `<h1>`; below 900px inside an `AppShellLayout` it is hidden visually because the mobile header already shows it. Inside a `PageShell`, `AppSettings` or `AppForm`, `EmptyState` and `FormSection` titles default to `<h2>` (under the page `<h1>`). Pass `headingLevel` to `EmptyState`, `FormSection` or `Card` to pick the level explicitly.

## Aside and reading width

Pass an `aside` snippet for a companion column (in-page index, summary, help, preview). When the shell itself is at least 60rem wide the aside sits next to the content (about 17rem, sticky); below that it follows the content. The breakpoint is the shell's width, not the viewport's, so an open `AppShellLayout` panel is accounted for. It renders as `<aside>`; name it with `asideLabel` when a page has more than one complementary landmark.

`width="reading"` caps the content column at 46rem so forms and settings keep a readable line length instead of stretching to `maxWidth`. With an aside the pair is centred. `width="wide"` (default) is the previous behaviour.

## Back button

`AppForm`, `AppSettings` and `PageShell` share one contract: `backHref` renders the standard back link in the leading position, and `onback(e)` may `preventDefault()` to take over. In a SvelteKit app with `<OverlayHistory />` mounted, use `back(fallback)` so Back returns to the previous in-app page, and to `fallback` when the page was the entry point (a deep link or a reload):

```svelte
<script>
  import { back } from "@codeatlasdev/ui/kit";
</script>

<AppForm title="Edit user" backHref="/users" onback={(e) => { e.preventDefault(); back("/users"); }}>
```
