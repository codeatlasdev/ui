```svelte
<script>
  import { PageShell, Button } from "@codeatlasdev/ui";
</script>

<PageShell title="Dashboard" description="Overview of this month">
  {#snippet actions()}<Button size="sm">New report</Button>{/snippet}
  <!-- page content -->
</PageShell>
```

`PageShell` never renders `<main>`. Inside `AppShellLayout` the shell is the `<main id="main">` landmark; on a page with no shell (a one-screen app) wrap it yourself, with a skip link first, or axe reports `landmark-one-main`:

```svelte
<script>
  import { PageShell, SkipLink } from "@codeatlasdev/ui";
</script>

<SkipLink />
<main id="main" tabindex="-1">
  <PageShell title="Pipeline">…</PageShell>
</main>
```

Inside `AppShellLayout` the full-width content region is the scroll container and `PageShell` is only the centred column, so the scrollbar sits at the window edge. Outside a shell `PageShell` scrolls itself.

A one-page app does not need `AppShellLayout` for this. See the [Standalone page](/docs/getting-started/recipes/#standalone-page) recipe.

Below 900px the header stacks: the description leads and `actions` wrap onto their own row. `Button`s share that row full-width (large tap targets); everything else (`IconButton`, `ThemeToggle`, `StatusChip`, `Chip`, `Badge`, plain text) keeps its natural size and stays at the end of the row.

The shell renders `title` as the page `<h1>`; below 900px inside an `AppShellLayout` it is hidden visually because the mobile header already shows it. Inside a `PageShell`, `AppSettings` or `AppForm`, `EmptyState` and `FormSection` titles default to `<h2>` (under the page `<h1>`). Pass `headingLevel` to `EmptyState`, `FormSection` or `Card` to pick the level explicitly.

## Action priority

The title column never gets narrower than 12rem: the `actions` block shrinks and gives way instead of taking its content width. Below 900px the title and description take the whole row and the actions sit on a row of their own, as before.

Put `data-priority="primary"` on the action that must always be reachable and the header keeps the actions on one line: the ones that do not fit move, in order, into a `DropdownMenu` behind a More `IconButton` at the end of the row (localized "More"/"Mais"). The row is measured with a `ResizeObserver`, so they come back when there is room. The actions stay in the DOM: picking a menu entry clicks the real button, so its handler runs. A menu entry is named by `data-overflow="Label"`, then the action's `aria-label`, then its text. Without a `data-priority="primary"` action nothing collapses and the actions wrap as they always did.

```svelte
<PageShell title="Atendimento ao cliente">
  {#snippet actions()}
    <Button>Exportar</Button>
    <Button>Importar</Button>
    <Button variant="filled" data-priority="primary">Novo</Button>
  {/snippet}
</PageShell>
```

## Icon tile, count and title extras

`icon` renders a decorative tile (22px icon in a brand-tinted rounded square) before the title; `count` renders a subtle `Badge` after it; `titleExtra` is a snippet for anything else inline with the title (a status badge, a filter chip). Size and tint of the tile come from `--ca-page-icon-size` (default `--ca-space-10`) and `--ca-page-icon-bg` (default the brand at 14%).

The count is part of the page's name: the `<h1>` reads "Deals, 128" to a screen reader (through its `aria-label`, which starts with the visible title; the visible badge is `aria-hidden` so it is not announced twice) and the `role="region"` named by it carries the same name. Below 900px inside an `AppShellLayout` the title is hidden because the mobile header shows it, but the icon tile, the count and `titleExtra` stay visible. A zero count shows; omit `count` to hide the badge.

## Aside and reading width

Pass an `aside` snippet for a companion column (in-page index, summary, help, preview). When the shell itself is at least 60rem wide the aside sits next to the content (about 17rem, sticky); below that it follows the content. The breakpoint is the shell's width, not the viewport's, so an open `AppShellLayout` panel is accounted for. It renders as `<aside>`; name it with `asideLabel` when a page has more than one complementary landmark.

`width="reading"` caps the content column at 46rem so forms and settings keep a readable line length instead of stretching to `maxWidth`. With an aside the pair is centred. `width="wide"` (default) is the previous behaviour.

## Back button

`AppForm`, `AppSettings` and `PageShell` share one contract: `backHref` renders the standard back link in the leading position, and `onback(e)` may `preventDefault()` to take over, for example to return to the previous in-app page instead of `backHref` when there is one:

```svelte
<script lang="ts">
  import { AppForm } from "@codeatlasdev/ui";

  function onback(e: MouseEvent) {
    // A page opened from inside the app goes back; a deep link or a reload follows backHref.
    if (document.referrer.startsWith(location.origin)) {
      e.preventDefault();
      history.back();
    }
  }
</script>

<AppForm title="Edit user" backHref="/users" {onback}>
  <p>Form fields</p>
</AppForm>
```
