```svelte
<script>
  import { Surface } from "@codeatlasdev/ui";
</script>

<Surface elevation={2} tone="brand" p="4">…</Surface>
<Surface as="section" material="glass" elevation={4}>…</Surface>
```

A Surface is one element painted by one CSS rule (`.ca-surface`). Each prop is a `data-*` attribute, and each attribute writes different `--ca-surface-*` variables, so the axes never fight: `elevation` is depth (shadow and the blur/fill tier), `material` is what the surface is made of, `tone` tints it, `variant` removes the fill or draws an outline, `radius` rounds it. Nothing is written to `style`.

`material="auto"` follows the theme: it reads the tokens that `<html data-style>` already rewrites, so an app on the solid style gets opaque surfaces and one on the `liquid` recipe gets glass, with no change to the component. The explicit materials ignore `data-style`: use `glass` for one blurred surface in a solid app, or `solid` to keep one opaque in a glass app. Glass needs something behind it to blur, which is why the demos sit on a gradient.

Rules the CSS follows, and you should too when you wrap a Surface: never `will-change: transform` on it or an ancestor, and never `isolation: isolate` on a parent of a glass or frosted surface. Both silently remove the backdrop blur. Under `prefers-reduced-transparency` translucent fills become opaque, and under `forced-colors` every surface gets a real `CanvasText` border.

## Data attributes

The attributes are part of the public CSS contract, so an app can restyle one axis without touching the component: `[data-elevation="0"]`, `[data-material="glass"]`, `[data-tone="error"]`, `[data-variant="ghost"]`, `[data-radius="pill"]`, `[data-interactive]`, `[data-glow]`.

## SurfacePanel

`SurfacePanel` is a Surface at elevation 2 that renders a `<section>`. With an accessible name (`aria-label` or `aria-labelledby`) it is a region landmark: a filter bar, a settings group, a summary beside a table. It is not the AppShell sidebar `Panel`.
