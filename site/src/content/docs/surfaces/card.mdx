```svelte
<script>
  import { Card } from "@codeatlasdev/ui";
</script>

<Card title="Team" headingLevel={2} tone="brand">…</Card>
```

Card is a [Surface](/docs/surfaces/surface/) with a header (`title`, `headerActions`), padding from `--ca-card-padding` and an optional link. Every Surface prop passes through (`elevation`, `material`, `tone`, `variant`, `radius`, `glow`, `interactive`), and `material="auto"` follows the theme: opaque under the default solid style, glass under `liquid`. The demos below set `material="glass"` so they look the same under any style. Use `flush` for content that touches the edges, such as tables, images and code.

**The content is already padded.** Card pads its children with `--ca-card-padding` (20px). A wrapper that adds its own padding (`<Card><div class="box">…</div></Card>` with `.box { padding: 1.25rem }`) doubles it to 40px, the usual cause of an oversized card. Remove the wrapper padding, pick a density with `padding` (`'none'`, `'sm'`, `'md'`, `'lg'`, a CSS length or a number of pixels), or use `flush` when you bring your own layout. In development a `[ca-ui]` warning names the mistake when the first child is padded. To change the default for the whole app, override `--ca-card-padding` on `:root`.

`title` is a paragraph unless you pass `headingLevel`, so adding a Card never changes a page outline by accident. Pass `headingLevel` to make the card a section under the page heading (a `PageShell` title is the `<h1>`, so cards start at `2`). Only the tag changes, never the look.

With `href` the card is a single `<a>` and is interactive. The link name comes from the content, so give the card a `title`.
