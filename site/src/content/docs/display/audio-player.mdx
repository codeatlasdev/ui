The native `<audio controls>` is unstyled and differs in dark mode and on iOS. This player keeps the `<audio>` element but draws its own controls. The `src` is attached on the first play (`preload="none"`), so a thread with fifty voice notes makes no request until you press play; pass `duration` so the UI is complete before that. The waveform is a `role="slider"`: drag or click to seek, Arrow keys move 5 seconds, Page Up and Page Down 10, Home and End jump. Starting one player pauses any other.

## On a chat bubble

Inside a bubble pass `tone="inherit"`: bars, chips and time come from the bubble's text colour and hold 3:1 (bars) and 4.5:1 (glyph, time) on both bubbles, light and dark. `variant="voice"` draws the glyph in `--ca-audio-surface`, which `MessageBubble` sets to its own background.

## Tokens

Set on the player or an ancestor; the bar count follows the live values and resizes.

- `--ca-audio-bar-w`: bar width, default `3px`.
- `--ca-audio-bar-gap`: gap between bars, default `2px`.
- `--ca-audio-wave-h`: waveform height, default `var(--ca-space-8)`.
- `--ca-audio-max-w`: largest player width, default `calc(var(--ca-space-24) * 3)`; `100%` fits the bubble.
- `--ca-audio-min-w`: smallest player width, default `0px`.
- `--ca-audio-surface`: surface behind a `voice` glyph; `MessageBubble` sets it.

WhatsApp peaks (base64, bytes 0 to 100): `Array.from(atob(b64), (c) => c.charCodeAt(0) / 100)`.
