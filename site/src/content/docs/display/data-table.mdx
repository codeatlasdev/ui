DataTable lives in its own entry point so that TanStack Table stays out of bundles that do not need it. Install the optional peer first.

```svelte
<script lang="ts">
  import { DataTable, createCaColumnHelper } from "@codeatlasdev/ui/table";
  type User = { name: string };
  const users: User[] = [{ name: "Ana Souza" }, { name: "Bruno Lima" }];

  const col = createCaColumnHelper<User>();
  const columns = col.columns([
    col.accessor("name", { header: "Name", meta: { label: "Name" } }),
  ]);
</script>

<DataTable {columns} data={users} />
```

There are two modes. In simple mode you pass `columns` and `data` and the table searches, sorts and paginates locally. In controlled mode you pass `globalFilter`, `pagination` and `sorting` together with their change handlers, and feed it one page of data plus `total`, which is what you want for server-side data.

## Groups, resize, reorder and interactive cells

Four options turn the table into a backlog or board in table form. They are independent: use any of them alone.

- **Row groups.** `groupBy={(row) => row.sprint}` renders one `<tbody>` per key, in first-appearance order, each with a header row. The header is a button with `aria-expanded` that collapses its rows; `groupLabel` replaces its content.
- **Column resize.** Set `meta: { resizable: true }` on a column, with `size`, `minSize` and `maxSize` on the definition. The header gets a handle that follows the window splitter pattern: drag it with a mouse, pen or finger, or focus it and press the arrow keys (10px, 40px with Shift), Home (minimum), End (maximum) and Enter (reset). Double click resets too. Once a column is resizable the table uses a fixed layout and scrolls sideways when its columns are wider than the container.
- **Row reorder.** `onReorder` adds a drag grip to every row, built on the [drag and drop primitive](/docs/foundation/drag-and-drop/): mouse, touch (press and hold) and keyboard (Space lifts, arrows move, Enter drops, Escape cancels), announced to screen readers. Groups exchange rows. `DataTable` never changes `data`: the handler gets `{ id, from, to }` with `{ group, index }` positions inside a group and you apply them. Give rows stable ids with `rowId`.
- **Interactive cells.** A cell can render any component (`renderComponent(Button, …)`, menus, inline editors). A click on a link, button, input or other control inside a cell does not reach `onRowClick`; mark any other element with `data-no-row-click` to opt it out too.

Only the current page is in the DOM, so a table of thousands of rows stays fast: raise `pageSize` (simple mode) or page on the server (controlled mode).

## Building blocks

`DataTable` is assembled from the parts below, all exported from `@codeatlasdev/ui/table`. You rarely need them: use them standalone when you render your own `<table>` markup around a table instance made with `createCaTable`, for example a layout `DataTable` does not offer. Inside `DataTable` the toolbar, pagination and column toggle are already wired. Use `DataTableColumnHeader` as a column `header` to get a sortable header, and pass `DataTableFacetedFilter` as `children` of `DataTable`.

```svelte
<script lang="ts">
  import { renderComponent } from "@tanstack/svelte-table";
  import { createCaColumnHelper, DataTableColumnHeader } from "@codeatlasdev/ui/table";
  type User = { name: string };

  const col = createCaColumnHelper<User>();
  const columns = col.columns([
    col.accessor("name", {
      header: ({ column }) =>
        renderComponent(DataTableColumnHeader<User, string>, { column, title: "Name" }),
      meta: { label: "Name" },
    }),
  ]);
</script>
```

`createCaColumnHelper`, `createCaTable`, `caTableFeatures` and the `CaColumn`, `CaColumnDef`, `CaColumnMeta`, `CaTable` and `CaTableFeatures` types are exported from the same entry point. `meta.label` is the name shown in the column visibility menu.
