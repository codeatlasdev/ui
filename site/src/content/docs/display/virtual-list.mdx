```svelte
<script>
  import { VirtualList } from "@codeatlasdev/ui";
</script>

<VirtualList {items} getKey={(m) => m.id} label="Conversation" {hasMore} loadingMore={loading} onloadmore={loadOlder}>
  {#snippet item(m)}<Message {m} />{/snippet}
</VirtualList>
```

Only the rows in view (plus `overscan`) are in the DOM; row heights are measured, so they can vary. Prepending older rows keeps the row you were reading in the same place: the list finds the previous first row by `getKey` and corrects `scrollTop`. `LiveList` follows the bottom but cannot prepend history without a jump; this one can, and also follows new rows while you are at the bottom. Two triggers ask for the same page: scrolling within `loadThreshold` (120 px) of the top, and a visible "Load older messages" button for keyboard and screen reader users; each page calls `onloadmore` once. The button is the first item of the content, a fixed-height block in the flow: it is in view only when the start of the history is, never covers a row, and its height is the same in every state, so nothing moves when the last page arrives. While `loadingMore` it stays the same element, labelled "Loading older messages…", with `aria-busy="true"` and `aria-disabled="true"` (a click does nothing, focus stays on it): scrolling to the button crosses the threshold, so the load usually starts on the way, and a test that clicks it, or a slow tap, still lands on a button. To exercise the scroll path in an end-to-end test, wheel over the list (`page.mouse.wheel(0, -60)` until the busy state shows) instead of clicking.

Passing a different list (the previous first row is gone, for example switching conversation) resets the scroll state and measured heights, and the new list opens at its end like a fresh mount; no `{#key}` is needed.
