import { Callout } from "@codeatlasdev/ui";

Pick the recipe that matches the screen you are building and copy it whole. Change only the data, the copy and the theme: the structure, the components and the slots are the part that is already right. When you are unsure about a prop, look it up with the `get_component` tool of the `ca-ui-mcp` server or in `API.md` instead of guessing.

Every example is a SvelteKit route file with its imports, its data shape and its state in view. Spacing props on `Flex`, `Stack` and `Grid` take steps of the spacing scale as strings (`gap="4"`), never pixels.

<Callout type="note" title="Written for SvelteKit 3">
  The recipes assume SvelteKit 3 (`@sveltejs/kit ^3`), the version `sv create` installs. Kit 3 has no `$lib`: the imports below read `#lib/messages.ts`, through the `imports` map `init` adds to `package.json`, with the extension. On SvelteKit 2 write the same import as `$lib/messages` (no extension), and likewise for every other `#lib/` import (`#lib/map-state.svelte.ts` is `$lib/map-state.svelte`). Nothing else in the recipes changes between the two majors, except that Kit 2 keeps its options in `svelte.config.js` instead of `sveltekit({ ... })`. See [Installation](/docs/getting-started/installation/#sveltekit-3).
</Callout>

## App shell

Use it once, in the layout of a route group that holds every authenticated page, so the rail, the panel and the mobile navigation wrap them all.

Every recipe reads its visible text from `src/lib/messages.ts` (see [App copy](/docs/getting-started/app-copy/)): `codeatlas-ui lint` reports literal text in a template as `i18n-literal`. The module below is shared by the App shell, List page, Form page, Settings page and Auth recipes. Each recipe shows the keys it reads; put them all in the one file.

```ts
// src/lib/messages.ts (the keys the app shell reads)
export const m = {
  brand: "Acme",
  nav: {
    main: "Main",
    dashboard: "Dashboard",
    users: "Users",
    settings: "Settings",
    workspace: "Workspace",
    profile: "My profile",
    search: "Search, command K",
  },
  account: { name: "Ana Lima" },
  notifications: [
    { title: "New user signed up", body: "Hana Park joined the Pro plan.", time: "2 min ago" },
    { title: "Monthly report ready", body: "September revenue is available.", time: "1 hr ago" },
  ],
  sections: "Sections",
  onThisPage: "On this page",
  workspaceSettings: {
    title: "Workspace settings",
    description: "Reading width keeps the form at a comfortable line length.",
    general: "General",
    billing: "Billing",
    name: "Name",
    slug: "Slug",
  },
} as const;
```

```svelte
<!-- src/routes/(app)/+layout.svelte -->
<script lang="ts">
  import {
    AppShellLayout,
    Avatar,
    Button,
    CommandPalette,
    NavMoreSheet,
    NotificationBell,
    ThemeToggle,
    Toaster,
    type NavModule,
    type NotificationItem,
  } from "@codeatlasdev/ui";
  import { goto } from "$app/navigation";
  import { page } from "$app/state";
  import { m } from "#lib/messages.ts";
  import { LayoutDashboard, Search, Settings, Users } from "@lucide/svelte";

  let { children } = $props();

  const modules: NavModule[] = [
    {
      id: "main",
      label: m.nav.main,
      icon: LayoutDashboard,
      basePath: "/dashboard",
      pathPrefixes: ["/users"],
      items: [
        { id: "dashboard", label: m.nav.dashboard, icon: LayoutDashboard, path: "/dashboard" },
        { id: "users", label: m.nav.users, icon: Users, path: "/users" },
      ],
    },
    {
      id: "settings",
      label: m.nav.settings,
      icon: Settings,
      basePath: "/settings",
      items: [
        { id: "workspace", label: m.nav.workspace, icon: Settings, path: "/settings" },
        { id: "profile", label: m.nav.profile, icon: Users, path: "/settings/profile" },
      ],
    },
  ];

  let notifications = $state<NotificationItem[]>(
    m.notifications.map((n, i) => ({
      id: String(i + 1),
      ...n,
      read: i > 0,
      variant: i === 0 ? "success" : "info",
    })),
  );

  const markRead = (id: string) =>
    (notifications = notifications.map((n) => (n.id === id ? { ...n, read: true } : n)));
  const markAllRead = () => (notifications = notifications.map((n) => ({ ...n, read: true })));
  const clear = () => (notifications = notifications.filter((n) => !n.read));

  let searchOpen = $state(false);
</script>

<AppShellLayout
  {modules}
  pathname={page.url.pathname}
  onNavigate={(path) => goto(path)}
  railLabels
  collapseShortPanel
  bottomNavPrimary={4}
  moreSheet={NavMoreSheet}
>
  {#snippet brand()}
    <strong>{m.brand}</strong>
  {/snippet}

  {#snippet railTop()}
    <Button variant="ghost" size="sm" aria-label={m.nav.search} onclick={() => (searchOpen = true)}>
      {#snippet leading()}<Search size={16} />{/snippet}
    </Button>
  {/snippet}

  {#snippet railBottom()}
    <ThemeToggle />
    <NotificationBell {notifications} onRead={markRead} onReadAll={markAllRead} onClear={clear} />
    <Avatar alt={m.account.name} size="sm" />
  {/snippet}

  {#snippet bottomNavOverflow()}
    <Button variant="outlined" tone="neutral" fullWidth href="/settings/profile">{m.nav.profile}</Button>
  {/snippet}

  {@render children()}
</AppShellLayout>

<CommandPalette {modules} bind:open={searchOpen} onNavigate={(path) => goto(path)} />

<!-- Mounted once for the whole app: every toast.success(...) in a page renders here. -->
<Toaster />
```

### With a stage (optional)

Skip this block unless the app has a persistent background layer (a map, a canvas, a video). It is not part of the base recipe above: with no `stage` the shell renders none. Add the two props and the snippet to the same layout:

```svelte
<!-- src/routes/(app)/+layout.svelte: the same layout, plus a stage -->
<script lang="ts">
  import { AppShellLayout, type NavModule } from "@codeatlasdev/ui";
  import { goto } from "$app/navigation";
  import { page } from "$app/state";

  let { children } = $props();
  // `modules` is the same array as above.
  const modules: NavModule[] = [];
</script>

<AppShellLayout
  {modules}
  pathname={page.url.pathname}
  onNavigate={(path) => goto(path)}
  {stage}
  stageVisible={!page.url.pathname.startsWith("/settings")}
>
  {@render children()}
</AppShellLayout>

<!-- A layer that lives behind every page and is mounted once: a map, a canvas, a video. -->
{#snippet stage({ hidden }: { hidden: boolean })}
  <canvas class="backdrop" class:paused={hidden}></canvas>
{/snippet}
```

`hidden` is true while `stageVisible` is false, so stop rendering then. `.backdrop` is yours to style: nothing in the package defines it. For a map, use the [Map page](#map-page) recipe instead of a hand-made stage.

A page inside the shell. For a form or settings page, `width="reading"` caps the column at about 46rem, and an `aside` snippet puts a section index next to it.

```svelte
<!-- src/routes/(app)/settings/workspace/+page.svelte -->
<script lang="ts">
  import { Card, PageShell, Stack, TextField } from "@codeatlasdev/ui";
  import { m } from "#lib/messages.ts";

  let name = $state("Acme Inc.");
  let slug = $state("acme");
</script>

<!-- Inside the app shell, which owns <main>. With no shell, see Standalone page. -->
<PageShell
  title={m.workspaceSettings.title}
  description={m.workspaceSettings.description}
  width="reading"
  asideLabel={m.sections}
>
  {#snippet aside()}
    <Card full>
      <nav aria-label={m.onThisPage}>
        <a href="#general">{m.workspaceSettings.general}</a>
        <a href="#billing">{m.workspaceSettings.billing}</a>
      </nav>
    </Card>
  {/snippet}

  <Card title={m.workspaceSettings.general} full gap="md" headingLevel={2}>
    <TextField label={m.workspaceSettings.name} bind:value={name} />
    <TextField label={m.workspaceSettings.slug} bind:value={slug} />
  </Card>
</PageShell>
```

Rules:

- Put it in `src/routes/(app)/+layout.svelte` and nowhere else. Never in the root layout: the root layout also wraps the landing page, the sign-in page and the error page, and none of them has a rail.
- The shell imports no router. Pass `pathname={page.url.pathname}` from `$app/state` (never the `$app/stores` store) and `onNavigate={(path) => goto(path)}`. Panel items are plain links; `onNavigate` only fires when the rail or the bottom navigation switches module.
- `NavModule.basePath` is where the rail icon goes, `items` fill the panel, and `pathPrefixes` claims pages that belong to the module but sit outside its `basePath`. Icons are `@lucide/svelte` components, not strings.
- Pages inside the shell render the content area only. They must not add their own `<main>`: the shell is the page landmark. Page layouts such as `AppList` and `AppForm` fill the area and scroll on their own.
- The `brand` snippet is the logo at the top of the rail and in the mobile header. Anything that must stay reachable on a phone (an avatar) goes in `railBottom`, with `mobileHeaderActions` for the mobile header.
- `railLabels` writes each module's label under its rail icon. `railTop` is the slot between the brand and the modules for a search or command-palette trigger: a ghost `Button` that opens a `CommandPalette` (which also opens on Cmd+K). `collapseShortPanel` shows only the rail for a module with 2 destinations or fewer, so a short list does not reserve a column of empty panel.
- Below 900px the bottom navigation holds `bottomNavPrimary` tabs (5 by default). With more modules the last tab is More, a dialog with the rest plus the `bottomNavOverflow` snippet (account, sign out), so no module is unreachable. `moreSheet={NavMoreSheet}` swaps that dialog for a swipe-to-dismiss `Sheet`; it is opt-in because it adds about 10 kB gzip.
- Optional, see [With a stage](#with-a-stage-optional): a `{#snippet stage({ hidden })}` is a persistent background (a map, canvas or video) rendered once under the pages, so a route change never remounts it and its camera survives. Stop rendering while `hidden` is true. Mark floating panels with `class="ca-stage-panel"`: the content area lets pointer events through to the stage. `stageVisible={false}` hides the stage without unmounting it, for a full-page route that covers it. For a whole map page use the map recipe, not a hand-made stage.
- `Toaster` is mounted here once, so pages in this group can call `toast.success(...)`. A route outside the group (the auth pages) that toasts needs its own `<Toaster />`; mount it in the root layout instead when both groups toast.
- Copy comes from `src/lib/messages.ts`, never from literals in the template. Copy the `ts` block above next to the route and edit the text there; see [App copy](/docs/getting-started/app-copy/).

See also: [AppShell](/docs/layout/app-shell/), [ThemeToggle](/docs/inputs/theme-toggle/), [NotificationBell](/docs/display/notification-bell/), [Avatar](/docs/display/avatar/), [Mobile](/docs/getting-started/mobile/), [App copy](/docs/getting-started/app-copy/).

## List page

Use it for any collection that needs search, filters and pages: users, orders, invoices. Pass the whole dataset and `AppList` runs search, filters, selection and pagination.

```ts
// src/lib/messages.ts (the keys the list pages read)
export const m = {
  users: {
    title: "Users",
    export: "Export",
    create: "New user",
    columns: { user: "User", role: "Role", status: "Status" },
    roles: { Admin: "Admin", Editor: "Editor", Viewer: "Viewer" },
    status: { active: "Active", inactive: "Inactive" },
  },
  leads: {
    selectAll: "Select all leads",
    select: (name: string) => `Select ${name}`,
    columns: { name: "Name", company: "Company", value: "Value" },
  },
```


For a dense, spreadsheet-like grid (hundreds of rows, a pinned name column, groups, a selected row) keep `SimpleTable` and switch it to `density="compact"`. You own the sort and the selection; the table only draws them.

```svelte
<!-- src/routes/(app)/leads/+page.svelte -->
<script lang="ts">
  import {
    Checkbox,
    SimpleTable,
    TableGroupRow,
    TableRow,
    TableSortHeader,
  } from "@codeatlasdev/ui";
  import { m } from "#lib/messages.ts";

  interface Lead {
    id: string;
    name: string;
    company: string;
    stage: "New" | "Won";
    value: number;
  }

  const leads: Lead[] = [
    { id: "l1", name: "Ana Souza", company: "Atlas Co", stage: "New", value: 12000 },
    { id: "l2", name: "Bruno Lima", company: "Nimbus", stage: "New", value: 8400 },
    { id: "l3", name: "Carla Dias", company: "Orbit", stage: "Won", value: 22000 },
  ];

  let sort = $state<"none" | "asc" | "desc">("none");
  let selectedId = $state<string | undefined>();
  let opened = $state<Record<string, boolean>>({ New: true, Won: true });

  const sorted = $derived(
    sort === "none"
      ? leads
      : [...leads].sort((a, b) => (sort === "asc" ? 1 : -1) * a.name.localeCompare(b.name)),
  );
  const stages = $derived([...new Set(sorted.map((lead) => lead.stage))]);
  const nextSort = () => (sort = sort === "none" ? "asc" : sort === "asc" ? "desc" : "none");
  const open = (lead: Lead) => (selectedId = lead.id);
</script>

<SimpleTable density="compact" stickyColumns={2} headerCase="sentence">
  <thead>
    <tr>
      <th scope="col"><Checkbox aria-label={m.leads.selectAll} /></th>
      <TableSortHeader {sort} onsort={nextSort}>{m.leads.columns.name}</TableSortHeader>
      <th scope="col">{m.leads.columns.company}</th>
      <th scope="col">{m.leads.columns.value}</th>
    </tr>
  </thead>
  {#each stages as stage (stage)}
    <tbody>
      <TableGroupRow colspan={4} collapsible bind:open={opened[stage]}>
        {#snippet label()}{stage}{/snippet}
      </TableGroupRow>
      {#if opened[stage]}
        {#each sorted.filter((lead) => lead.stage === stage) as lead (lead.id)}
          <TableRow selected={selectedId === lead.id} onactivate={() => open(lead)}>
            <td><Checkbox aria-label={m.leads.select(lead.name)} /></td>
            <td class="primary">{lead.name}</td>
            <td>{lead.company}</td>
            <td>{lead.value.toLocaleString("en-US", { style: "currency", currency: "USD" })}</td>
          </TableRow>
        {/each}
      {/if}
    </tbody>
  {/each}
</SimpleTable>
```

Rules:

- Render rows from `list.rows` (the current page after search and filters), not from your own array. `list.filters`, `list.setFilter(key, value)`, `list.selected` and `list.toggleRow(id)` are on the same `list` object each snippet receives.
- `list` is typed from `data`: `T` is inferred, so `list.rows` are `User[]` and `user.email` is checked. To name the type yourself, annotate the parameter: `{#snippet children(list: UseListStateReturn<User>)}` (`UseListStateReturn` is exported from `@codeatlasdev/ui`). Leave the parameter untyped and Svelte infers it from `AppList`.
- `FilterGroup` adds an "all" option itself. Read its value with `list.filters[key] ?? "all"`.
- `AppList` has no own docs page: it is documented on the page layouts page. It fills its parent, so inside the app shell it needs no wrapper.
- Server-side pagination is the manual mode: omit `data`, render your own `toolbar` and `footer` snippets, and drive the rows from the `load` function. For a heavy grid (sorting, column sizing, thousands of rows) use `DataTable` from `@codeatlasdev/ui/table`, which needs `@tanstack/svelte-table`.
- Use `SimpleTable` for plain rows. Pass `responsive="cards"` to turn rows into cards on a phone. `density="compact"` keeps rows to 40px, `stickyColumns={2}` pins the checkbox and the name while the table scrolls sideways, `headerCase="sentence"` drops the uppercase labels, and `frame={false}` removes its border inside an already framed panel (`scroll="none"` when you own the scroller).
- In a dense table, a sortable header is `TableSortHeader` (`sort`, `onsort`: you own the state and the next direction), a clickable or selectable row is `TableRow` (`selected`, `onactivate`: Tab, Enter and Space work, and controls inside the row do not trigger it) and a group label is `TableGroupRow` (`colspan`, `collapsible`, `bind:open`, with your own `{#if open}` for the rows). Do not make a `<tr onclick>`.
- An export is a client-side download: `downloadFile(name, toCsv(rows), "text/csv")` (both from `@codeatlasdev/ui`, `toJson` for JSON) from a `Button onclick`. Never a link to a route you have not written (`/users/export`): a prerendered page that links to a missing route fails the build.
- Put the toolbar actions in the `actions` snippet: the brand action is `filled`, a secondary one is `variant="outlined" tone="neutral"` (or `ghost`), so it carries no brand color beside the primary.
- Data values that people read (a role, a status, a stage) are copy too: map them through `messages.ts` (`m.users.roles[user.role]`) and keep the raw value for filtering and keys. Names, emails and numbers from your data are not copy.

See also: [Page layouts (AppList)](/docs/layout/list-page/), [Table](/docs/display/table/), [DataTable](/docs/display/data-table/), [Chip](/docs/display/chip/), [FilterGroup](/docs/inputs/filter-group/), [App copy](/docs/getting-started/app-copy/).

## Form page

Use it for a create or edit screen: a header with a back button, a scrolling body of sections and a footer that stays in view.

```ts
// src/lib/messages.ts (the keys the form page reads)
export const m = {
  userForm: {
    title: "New user",
    description: "Fill in the details to invite a user.",
    account: { title: "Account", description: "Basic information about the user." },
    name: "Full name",
    email: "Work email",
    role: "Role",
    roles: { admin: "Admin", editor: "Editor", viewer: "Viewer" },
    notifications: "Notifications",
    welcome: "Send a welcome email",
    cancel: "Cancel",
    submit: "Create user",
    errors: { name: "Enter a name.", email: "Enter a valid email." },
    created: "User created",
    undo: "Undo",
  },
} as const;
```

```svelte
<!-- src/routes/(app)/users/new/+page.svelte -->
<script lang="ts">
  import { goto } from "$app/navigation";
  import {
    AppForm,
    Button,
    ChipGroup,
    FormSection,
    Switch,
    TextField,
    toast,
    useForm,
  } from "@codeatlasdev/ui";
  import { m } from "#lib/messages.ts";

  const f = m.userForm;
  const roleOptions = [
    { value: "admin", label: f.roles.admin },
    { value: "editor", label: f.roles.editor },
    { value: "viewer", label: f.roles.viewer },
  ];

  const form = useForm(
    { name: "", email: "", role: "viewer" },
    {
      schema: (data) => ({
        ...(data.name.trim() ? {} : { name: f.errors.name }),
        ...(data.email.includes("@") ? {} : { email: f.errors.email }),
      }),
    },
  );

  let sendWelcome = $state(true);
  let saving = $state(false);

  async function save() {
    if (!form.validate()) return;
    saving = true;
    try {
      const response = await fetch("/api/users", {
        method: "POST",
        headers: { "content-type": "application/json" },
        body: JSON.stringify({
          name: form.fields.name.value,
          email: form.fields.email.value,
          role: form.fields.role.value,
          sendWelcome,
        }),
      });
      const { id } = await response.json();
      toast.success(f.created, {
        description: form.fields.email.value,
        action: { label: f.undo, onClick: () => fetch(`/api/users/${id}`, { method: "DELETE" }) },
      });
      await goto("/users");
    } finally {
      saving = false;
    }
  }
</script>

<AppForm title={f.title} description={f.description} backHref="/users">
  <FormSection title={f.account.title} description={f.account.description}>
    <TextField
      label={f.name}
      required
      value={form.fields.name.value}
      error={form.fields.name.error}
      oninput={(value) => form.set("name", value)}
      onblur={() => form.touch("name")}
    />
    <TextField
      label={f.email}
      type="email"
      required
      value={form.fields.email.value}
      error={form.fields.email.error}
      oninput={(value) => form.set("email", value)}
      onblur={() => form.touch("email")}
    />
    <ChipGroup
      label={f.role}
      items={roleOptions}
      required
      value={form.fields.role.value}
      error={form.fields.role.error}
      onchange={(value) => form.set("role", value)}
    />
  </FormSection>

  <FormSection title={f.notifications} layout="list">
    <Switch label={f.welcome} bind:checked={sendWelcome} />
  </FormSection>

  {#snippet footer()}
    <Button variant="ghost" href="/users">{f.cancel}</Button>
    <Button variant="filled" loading={saving} onclick={save}>{f.submit}</Button>
  {/snippet}
</AppForm>
```

Rules:

- `useForm` holds every value as a string and shows an error only after a field is touched. Wire each field with `value`, `error`, `oninput` and `onblur`, and call `form.validate()` before submitting: it touches every field and returns whether they all pass.
- The back button comes from `backHref`. Do not build a header, a back link or a sticky bar by hand: `title`, `description`, `backHref` and the `footer` snippet are the header and the footer.
- Lay fields out with `FormSection`, not a wrapper `Stack`. `layout` is `grid` (default), `list` (rows of switches) or `stack`.
- Show progress with `loading` on the submit `Button`, not by swapping its label. Keep Cancel as a `ghost` button and the primary action as `filled`, last.
- A `Switch` or `Checkbox` is a boolean, so keep it in `$state` and `bind:checked`. Do not put it in `useForm`, which is strings only.
- A single choice among a few options is `ChipGroup` (a radiogroup of chips that wraps on a phone), not a `Select`: `items` are `{ value, label }`, `label` is the group name, `error` shows under it and `required` blocks a plain submit until one is picked. Use `Select` for a long list.
- Confirm a save with `toast.success(message, { description, action })`, not a custom banner. `action: { label, onClick }` adds one inline button (an Undo). Pass `{ id }` to replace a toast in place, as a "Saving..." that becomes "Saved". Identical messages stack as a count and at most 3 show at once.
- `toast` renders nothing until a `<Toaster />` is mounted. Inside the [app shell](#app-shell) recipe it already is, in `(app)/+layout.svelte`. A form outside it (a standalone page) mounts `<Toaster />` once in its layout, never per page.
- Validation messages and toast text are copy: they live in `messages.ts` like labels (`f.errors.name`), not as literals in `schema` or `toast`. Only `.svelte` templates are linted, but the same module keeps every language in one place.

See also: [AppForm](/docs/layout/form-page/), [useForm](/docs/inputs/use-form/), [TextField](/docs/inputs/text-field/), [ChipGroup](/docs/inputs/chip-group/), [Toast](/docs/feedback/toast/), [Switch](/docs/inputs/switch/), [App copy](/docs/getting-started/app-copy/).

- `AuthLayout` renders the page `<main id="main">`. Do not wrap it in another `<main>`, and do not put the app shell around it: auth routes live in their own group, outside `(app)`.

- `novalidate` on the `<form>` is what lets the library's `error` message show. - Build the form with `Stack` and `TextField`, and a `Button type="submit"` with `fullWidth` and `loading`. Set `autocomplete` (`email`, `current-password`, `new-password`) so password managers work. A password field is `type="password"` with `revealable` (an eye toggle inside the field), never a hand-made button; a "Forgot password?" link goes in its `below` snippet.
- The "Forgot password?" link is optional: it points at a `/forgot-password` route you build yourself (the same `AuthLayout` and `AuthCard` with one email field). An app with no password reset deletes the whole `below` snippet instead of linking to a page that does not exist.
- `panelSide` (`left` or `right`), `panelBleed` (the panel fills edge to edge: no padding, logo or blobs, and the `brand` and `logoName` are not drawn there), `panelHidden` (`md` 900px or `lg` 1200px, from which the panel shows) and `align="start"` with `AuthCard variant="plain"` give a form-first page. The `header` snippet is a sticky bar over the form column and replaces the mobile brand strip.
- Below the `panelHidden` width the panel is hidden and `mobileBrand` (on by default) shows a compact brand strip, so put nothing essential in `panel`. `AuthCard display` sets its title in the display role.
- The language names in `LocaleSwitcher` options (`English`, `Português`) are the one exception to the copy rule: they are `label` keys of a data array, not template attributes, and each language is written in itself on purpose. Everything else, including the error and the footer links, comes from `messages.ts`.

- A number tile is `KpiCard` inside a `KpiGrid`, with `trend` as a percentage and `icon` as a `@lucide/svelte` component. - Each chart or table goes in a `Card` with a `title`. A table that should touch the card edges is `Card padding="none"` around a `SimpleTable`; give it a `<caption class="ca-sr-only">`. A card that holds several blocks (a `Stat`, a `Progress`, a `TextField`) takes `gap="md"` so they stack with space between them.
- `PageShell` is the page container: `title`, `description`, the `actions` snippet and the spacing between blocks. Its `gap` is a number in px, unlike `Flex`, `Stack` and `Grid`, which take spacing steps. A thin bar is `Progress size="sm"`; `Surface grain` adds the paper-grain overlay to a panel that is not a `Card`.
- Inside the app shell this page needs no extra wrapper. Without a shell, follow [Standalone page](#standalone-page). Charts render on the client, so SSR shows the card and the chart fills in after hydration.

## Map page

Use it when a live map (or canvas, video, 3D) is the page and the forms, lists and details float over it. `AppShellLayout` mounts the stage once, so the camera and the deck.gl layers survive every navigation; `PageFrame` lays the page out over the stage and reports what it covers. Install the peers: `bun add maplibre-gl` (or `mapbox-gl` with `engine="mapbox"` and an `accessToken`), and for data layers `@deck.gl/core @deck.gl/mapbox @deck.gl/layers`, all `@deck.gl/*` on the same minor.

The layout holds the stage and the page holds the panel, so they share one small state module: the results, the selected id and the map handle.

```ts
// src/lib/map-state.svelte.ts
import type { MapInstance } from "@codeatlasdev/ui/map";

export interface Place {
  id: string;
  name: string;
  coordinates: [number, number];
}

class MapState {
  places = $state<Place[]>([]);
  selectedId = $state<string | null>(null);
  map = $state.raw<MapInstance | null>(null);

  select(place: Place) {
    this.selectedId = place.id;
    // MapStage's own helper is not public: use the engine's map from `onmapready`.
    const options = { center: place.coordinates, zoom: 12 };
    const reduced = matchMedia("(prefers-reduced-motion: reduce)").matches;
    if (reduced) this.map?.jumpTo(options);
    else this.map?.flyTo(options);
  }
}
```

Rules:

- Mount `MapStage` in the shell's `stage` snippet, not in a page: a page mount would recreate the map on every navigation. The layout and the page are different components, so they talk through a module-level `$state` class (`map-state.svelte.ts`, with the `.svelte.ts` extension so runes compile) or a context set in the layout: filters, the selection and the map handle live there.
- The only public handle on the camera is `onmapready(map)`, the engine's map (`flyTo`, `jumpTo`, `easeTo`). Keep it in the shared state and call it from the result list to recenter. `MapContext.move`, which `MapStage` uses internally to fall back to `jumpTo`, is not exported, so check `prefers-reduced-motion` yourself as above. `onmapready` runs once after the first style loads: the map is `null` before that.
- A pin that selects a row is a deck.gl layer with `pickable: true` and `onClick`; set `updateTriggers` for any accessor that reads the selection, or the layer keeps the old colors. Layers come from `@deck.gl/layers`: install it with `@deck.gl/core` and `@deck.gl/mapbox`.
- An offline basemap is a style object with one `background` layer. Take its color from `mapColors().surface` through `rgbaCss`, inside a `$derived`, so it follows the theme; a hex in a style object fails `codeatlas-ui lint`. For real tiles pass a style URL per scheme: that needs network, so keep the offline background wherever the app must work without it.
- `ScatterplotLayer` radii are in meters by default (`radiusUnits: "meters"`), so a 500 m dot is a speck on a country-wide map. For markers (pins, places) set `radiusUnits: "pixels"` and give `getRadius` pixel values: the dot keeps its size at every zoom. Keep meters only for a true geographic area (a 5 km coverage circle), and then add `radiusMinPixels` so it stays visible zoomed out.
- `MapStage` pads `fit` by what the frame covers, so it needs no `padding` prop. Read `stageInsets.current` (or `--ca-stage-inset-*` on `html`) for anything you position by hand, and never copy the panel widths. A legend you place with `stageInsets.left` sits under the bottom sheet on a phone, where the insets are at the bottom: hide it below 900px or offset it by `stageInsets.current.bottom` too.
- `mode="page"` (or `stageVisible={false}`) for a route that covers the map; `mode="split"` for a work area beside a map strip.
- With `sheet`, the panel is a non-modal bottom sheet on phones: the map above it stays interactive and the `toolbar` snippet is hidden at the `peek` detent (it shows the header only). Do not wrap it in `Sheet`. `bind:detent` takes `"peek" | "half" | "full"`.
- Colors for deck.gl layers come from `mapColors()` or `useMapTheme()` (both reactive), never from `getComputedStyle`. Empty areas of the page pass pointer events to the stage; give your own floating panels `class="ca-stage-panel"`.
- A one-screen map with no other destinations does not need the shell: see [Map page without a shell](#map-page-without-a-shell).

### Map page without a shell

`PageFrame` does not need `AppShellLayout`: it fills its parent and floats the panel inside it, so any `position: relative` box with a height works as the stage host. For a single map screen, put `MapStage` and `PageFrame` in that host inside your own `<main>`, and share state with a plain module as above. There is no rail, panel or bottom navigation, so no one-icon rail either.

- Delete the `<Seo>` that `init` put in `src/routes/+layout.svelte` when the page has its own: every `<Seo>` writes its tags into `<head>`, and only the `<title>` of the page replaces the layout's. The layout's `description`, `canonical` and `og:*` tags would stay next to the page's, so a crawler reads two. One `<Seo>` per page (SEO page: [the Seo component](/docs/getting-started/seo/#the-seo-component)), in the page or in the layout, never both. A layout `<Seo>` is only right when every route shares it unchanged.
- A landing page is not an app page: no `AppShellLayout`. Put it in the root route or a `(marketing)` group, with its own `<main id="main" tabindex="-1">`. The `SkipLink` is yours too: put one before `SiteHeader` when the header is not inside a shell.
- Build the page from `Container` (width and gutter), `Section` (vertical rhythm, a real `<section>`: give it `aria-labelledby`) and `Stack`, `Flex`, `Grid` for arrangement. `Grid` takes `columns` (1 to 12, or a responsive object) and a step `gap`; for a template like `2fr 1fr`, write the `grid-template-columns` in a class. A pricing table has no component of its own, and the recipe shows it: a `Grid columns={{ base: 1, md: 3 }}` of `Card`s, the price in `Heading size="display-3"`, the features in `Stack as="ul"`, `class="ca-pricing-cta"` on each `Button` (it pins the button to the bottom of the card), and a `Badge tone="brand" subtle` in `headerActions` for the highlighted plan. There is no footer component either: a `<footer aria-label>` with a `Container`, a `Divider` and plain links.
- `SiteHeader` is a sticky bar with a breadcrumb that is empty outside an app shell; the site navigation goes in its `trailing` snippet, which stays on the right. Put the `NavigationMenu` there as a direct child (not wrapped in a `div`): below 600px the header hides it, and a phone gets the same links from a `Drawer` opened by an `IconButton` that you show only below 600px. Keep at most the `LocaleSwitcher` and one CTA beside it in the bar: at 390px a second button does not fit. `LocaleSwitcher compact` always shows the short code.
- Switching language inside the page needs no navigation: bind `LocaleSwitcher` to a `$state` locale, derive your copy from it (`messages[locale]`) and pass the same value to `I18nProvider locale={locale}`, which is reactive, so the package's own strings follow. To give each language its own URL, use ``onselect={(next) => goto(`/${next}`)}`` instead (it may return a promise; `value` changes once it settles) and read the locale from the route.
- CTAs are `Button` with `href`: it renders a link, so no `onclick` navigation. One `filled` per view, the rest `outlined` or `ghost`; add `tone="neutral"` to an `outlined` or `ghost` button that sits beside the brand one. A tag on a card (a plan name, "New") is `Badge tone="brand" subtle`, not a `Chip`.
- The hero headline is `Heading size="display"`, never a styled `h1`. `level` sets the tag and `size` the look. `Heading` takes no `id` (see [Heading](/docs/display/heading/)), so the title that names a `Section` is a plain `<h2 id="features-title">` with `aria-labelledby` on the `Section`, as above; the hero names itself with `aria-label`. `Highlight` and `StrikeThrough` take `animated` to play on mount; under reduced motion they render fully drawn.
- `ThemeIsland` keeps this page in its own scheme (and `preset`) inside a dark app. Add `document` for a full page so `<html>` follows it and is restored on leaving, and set `setRouteTheme` on the server (see [Theming](#theming)) so the first paint is already right.
- Put `Seo` on every public page with `title`, `description` and an absolute `canonical`. With in-page language switching the page has one URL, so keep one canonical; use `alternates` only when each language has its own. The FAQ is an `Accordion type="single"` (one answer open at a time) and the same questions feed `faqPage(...)` into `jsonLd`, so the markup crawlers read is the text people see. Pass `lang` with an in-page language switch: `Seo` keeps `<html lang>` in step on the client and sets `og:locale`, which the `LocaleSwitcher` alone does not do. The `<html lang>` the server writes still belongs in `app.html`. Use `noindex` on app and auth pages.
- Static hosting (`adapter-static`): set `export const prerender = true;` in the root `+layout.ts` so `/` is built. The recipe links only to in-page anchors (`#features`, `#pricing`, `#faq`) and to `/sign-up` and `/sign-in`, which the Auth pages recipe defines; every plan CTA goes to `/sign-up`, so copying the page whole prerenders. SvelteKit fails the build when a prerendered page links to a route that does not exist yet (a `/pricing` or `/docs` you add to the nav): create the routes, or set `prerender: { handleHttpError: "warn" }` in the `sveltekit({ ... })` options until they exist. `adapter-static@4` needs Kit 3, so a Kit 2 app installs `@sveltejs/adapter-static@3`.

See also: [Layout primitives](/docs/layout/layout-primitives/), [Card](/docs/surfaces/card/), [Accordion](/docs/surfaces/accordion/), [Heading](/docs/display/heading/), [Button](/docs/inputs/button/), [NavigationMenu](/docs/navigation/navigation-menu/), [Drawer](/docs/feedback/drawer/), [i18n](/docs/getting-started/i18n/), [SEO](/docs/getting-started/seo/).

## Standalone page

Use it when the whole app is one screen (a single dashboard, a board, a map tool) and there is no rail or bottom navigation to host. Do not mount `AppShellLayout` for it: with one module it still draws a one-icon rail, a mobile header and a bottom bar. The page owns its landmark instead.

```ts
// src/lib/messages.ts (the keys the standalone page reads)
export const m = {
  standalone: {
    title: "Pipeline",
    description: "Open deals by stage",
    newDeal: "New deal",
  },
} as const;
```

```svelte
<!-- src/routes/+page.svelte -->
<script lang="ts">
  import { Button, PageShell, SkipLink } from "@codeatlasdev/ui";
  import { m } from "#lib/messages.ts";

  const p = m.standalone;
</script>

<SkipLink />
<main id="main" tabindex="-1">
  <PageShell title={p.title} description={p.description} maxWidth="1200px">
    {#snippet actions()}
      <Button variant="filled" size="sm">{p.newDeal}</Button>
    {/snippet}
    <!-- the screen: KpiGrid, Grid of Cards, Kanban, ... -->
  </PageShell>
</main>
```

Rules:

- `PageShell` never renders `<main>`: it assumes a shell or the page already has one. Without the wrapper axe reports `landmark-one-main`. Put one `<main id="main" tabindex="-1">` around it and a `SkipLink` before it (its `href` defaults to `#main`). One page, one `<main>`, one `id="main"`.
- `AppShellLayout` is for apps with several destinations. If a one-page app uses it anyway, pass `mainId={null}` and render your own `<main id="main" tabindex="-1">`, or keep the default and render no `<main>` of your own. Never both.
- A board or a table that must fill the screen needs a parent with a height. Give your own wrapper a class with `height: calc(var(--ca-vh) - 6rem)` (never `100vh`) rather than a `:global` rule on a `ca-*` class.
- Add `<RouteAnnouncer />` (`@codeatlasdev/ui/kit`) once in the root layout if the app has more than one route, and `<Seo>` with a `canonical` (or `noindex`) on the page.
- A map-first one-page screen is the same idea with a stage behind it: see [Map page without a shell](#map-page-without-a-shell).

See also: [PageShell](/docs/layout/page-shell/), [SkipLink](/docs/layout/skip-link/), [Accessibility](/docs/getting-started/accessibility/#skip-link-and-landmarks).

## Theming

Use it to set the brand color, fonts, radius and surface style for the whole app from one object, with no per-component styling.

```ts
// src/lib/theme.ts
import type { ThemeOptions } from "@codeatlasdev/ui/vite";

export const theme: ThemeOptions = {
  presets: [
    {
      id: "acme",
      color: "#2563eb",
      label: "Acme",
      // Optional: the brand itself as the dark-mode button fill, with its text color.
      colors: { dark: { brandFill: "#2563eb", brandFillHover: "#3b82f6", brandContrast: "#ffffff" } },
      // Optional: a smaller font in every text field, in both schemes.
      sizes: { inputFontSize: "0.875rem" },
    },
  ],
  defaultPreset: "acme",
  defaultScheme: "system",
  defaultStyle: "solid",
  fonts: { body: "Geist, system-ui, sans-serif", display: "Fraunces, serif" },
  typography: { displayTracking: "-0.03em" },
  radius: 0.8,
};
```

```ts
// vite.config.ts
import { sveltekit } from "@sveltejs/kit/vite";
import { caErrorPlugin, caThemePlugin } from "@codeatlasdev/ui/vite";
import { defineConfig } from "vite";
import { theme } from "./src/lib/theme.ts";

export default defineConfig({
  plugins: [sveltekit(), caThemePlugin(theme), caErrorPlugin({ scaffold: true, theme })],
});
```

```ts
// src/hooks.server.ts
import { sequence } from "@sveltejs/kit/hooks";
import { caThemeHandle, createErrorHandler } from "@codeatlasdev/ui/kit";
import { theme } from "$lib/theme";

export const handle = sequence(caThemeHandle(theme));
export const handleError = createErrorHandler();
```

```css
/* src/app.css: imported after @codeatlasdev/ui/styles/global.css */
:root {
  --ca-card-padding: 20px;
  --ca-font-size-body1: 0.875rem;
}
```

```ts
// src/routes/(marketing)/+layout.server.ts: a light route inside a dark app, themed on the first paint
import { setRouteTheme } from "@codeatlasdev/ui/kit";

export const load = (event) => {
  setRouteTheme(event, { preset: "acme", scheme: "light" });
};
```

```ts
// src/hooks.server.ts: or declare a whole route group once
import { caThemeHandle, type RouteThemes } from "@codeatlasdev/ui/kit";
import { theme } from "$lib/theme";

const routes: RouteThemes = { "/(marketing)": { preset: "acme", scheme: "light" } };

export const handle = caThemeHandle(theme, { routes });
```

Rules:

- One `ThemeOptions` object in `src/lib/theme.ts`, passed to both `caThemePlugin(theme)` and `caThemeHandle(theme)`. Called with no argument, either one falls back to the default brand and ignores your presets.
- A brand color is a preset: give it a `#rrggbb` and the full light and dark token set is generated. Do not copy colors into component styles.
- Import the theme in `vite.config.ts` with the `.ts` extension. Everything else (preset, scheme, style, fonts, radius, density) is a field of the same object.
- To change one token, declare it on `:root` as `--ca-*`, without `!important`. Never write hex colors or pixel sizes in a component. For denser body text override only `--ca-font-size-body1`: it sizes the text on `body` and does not depend on the root rem, so never set `html { font-size: ... }`, which would rescale every label, input and button.
- `brandFill`, `brandFillHover` and `brandContrast` under `colors.dark` make `Button variant="filled"` use the brand color itself in dark mode, with `brandContrast` as its text. `sizes.inputFontSize` is a plain length (`px`, `rem`, `em`). Both belong to the preset, never to app CSS.
- Display text (`Heading size="display"`, the `display` prop of `PageShell`, `AuthCard` and `SiteHeader`) reads `--ca-font-display`, which `fonts.display` sets, and `typography.displayTracking`. Never set a font family in a component.
- A page that must keep another preset or scheme than the app (a light landing in a dark app) renders `<ThemeIsland document>`. Pair it with `setRouteTheme` from `@codeatlasdev/ui/kit` in `load`, or `routes` in `caThemeHandle`, so the server response already has that theme and nothing flashes.
- Colors that are not UI roles (status, tier, channel, map pins) go under `tokens` on the preset, not in a `domain.css`: `tokens.status.new` gives `--ca-token-status-new` (+ `-subtle`, `-contrast`) per scheme, and `tokenRgba("status.new")` gives `[r, g, b, a]` for canvas and maps. A role color may carry alpha (`oklch(1 0 0 / 0.62)` or `{ color, alpha }`): do not flatten it to a hex.
- `bunx @codeatlasdev/ui init --write` creates and patches all of these files, and is a dry run without `--write`.

See also: [Theming](/docs/getting-started/theming/), [Installation](/docs/getting-started/installation/).

## When the recipe does not fit

- Several components could do the job: read the decision tables in [Choosing components](/docs/getting-started/choosing/) before improvising.
- You are about to write a wrapper, a hand-made header or an override: check [Common workarounds](/docs/getting-started/workarounds/) for the component that already does it.
- You want a reference to adapt: browse the [gallery](/gallery/) and port a numbered demo. In the MCP server call `search_demos`, or fetch `/api/v1/en/e/NNN.txt` for demo `NNN`.
- The library is missing something or gets in the way: call `report_issue` (see [Reporting problems](/docs/getting-started/reporting/)) instead of shipping a workaround in the app.
