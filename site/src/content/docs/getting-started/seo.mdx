`@codeatlasdev/ui/seo` covers what a public page needs to be found, shared and read by crawlers and AI assistants. It has no peer dependency beyond Svelte: the `Seo` component renders into `<svelte:head>` during SSR or prerender, and everything else is plain TypeScript that returns strings or objects. Nothing runs in the browser.

```ts
import {
  Seo, // component
  organization, website, softwareApplication, product, faqPage, breadcrumbList, article, graph, // JSON-LD
  sitemapXml, robotsTxt, // crawler files
  llmsTxt, markdownNegotiation, // AI readers
  ogImageRoute, ogCard, // social images
  iconLinks, // favicon, apple-touch-icon and manifest links
  manifest, appleMeta, // PWA (see the PWA page)
} from "@codeatlasdev/ui/seo";
```

## The Seo component

Place one `Seo` per page, in the route or layout that knows the page's data.

```svelte
<script>
  import { Seo, graph, organization, website } from "@codeatlasdev/ui/seo";
  import { page } from "$app/state";

  const origin = "https://acme.com";
</script>

<Seo
  title="Pricing"
  titleTemplate="%s · Acme"
  description="Plans for teams of any size."
  canonical={origin + page.url.pathname}
  og={{ image: `${origin}/og/pricing.jpg`, imageAlt: "Acme pricing", siteName: "Acme", locale: "en_US" }}
  twitter={{ site: "@acme" }}
  alternates={[
    { hreflang: "en", href: `${origin}/pricing` },
    { hreflang: "pt-BR", href: `${origin}/pt/pricing` },
    { hreflang: "x-default", href: `${origin}/pricing` },
  ]}
  jsonLd={graph(
    organization({ id: `${origin}/#org`, name: "Acme", url: origin }),
    website({ name: "Acme", url: origin, publisher: { "@id": `${origin}/#org` } }),
  )}
/>
```

<Callout type="info" title="Where the dev warnings come from">
  In development `Seo` warns when an indexable page has no `canonical`, and `caThemeHandle` warns once per problem when the final HTML has no `viewport-fit=cover`, a viewport meta that blocks zoom (`user-scalable=no`, `maximum-scale=1`) or no `lang` on `<html>`. Production builds stay silent.

## Structured data

The builders return plain objects with `undefined` fields removed. Give a node an `id` and reference it from others with `{ "@id": ... }`, then join everything with `graph()`.

| Builder | Use it for |
|---|---|
| `organization` | Company identity, logo, `sameAs` profiles. |
| `website` | Site root. `searchUrlTemplate: "https://acme.com/s?q={query}"` adds the sitelinks `SearchAction`. |
| `softwareApplication` | SaaS and app landing pages, with optional `offer` and `rating`. |
| `product` | Store pages: one or several `offers`, price, currency and availability. |
| `faqPage` | Question and answer lists that are visible on the page. |
| `breadcrumbList` | Trail from the root; omit `href` on the current page. |
| `article` | Blog posts and docs (`type: "BlogPosting" | "NewsArticle" | "TechArticle"`). |

```ts
import { product } from "@codeatlasdev/ui/seo";

product({
  name: "Ceramic mug",
  image: ["https://shop.example/mug.jpg"],
  brand: "Acme",
  offers: { price: 49.9, priceCurrency: "BRL", availability: "InStock" },
});
```

## Sitemap and robots.txt

Both are plain strings, meant for prerendered `+server.ts` routes.

```ts
// src/routes/sitemap.xml/+server.ts
import { sitemapXml } from "@codeatlasdev/ui/seo";

export const prerender = true;

export function GET() {
  const body = sitemapXml(
    ["/", "/pricing", "/docs"].map((path) => ({
      loc: `https://acme.com${path}`,
      lastmod: new Date(),
      alternates: [
        { hreflang: "en", href: `https://acme.com${path}` },
        { hreflang: "pt-BR", href: `https://acme.com/pt${path}` },
        { hreflang: "x-default", href: `https://acme.com${path}` },
      ],
    })),
  );
  return new Response(body, { headers: { "content-type": "application/xml" } });
}
```

```ts
// src/routes/robots.txt/+server.ts
import { robotsTxt } from "@codeatlasdev/ui/seo";

export const prerender = true;

export const GET = () =>
  new Response(robotsTxt({ sitemap: "https://acme.com/sitemap.xml", disallow: ["/app", "/admin"] }), {
    headers: { "content-type": "text/plain" },
  });
```

`sitemapXml` throws above 50,000 URLs, the protocol limit: split larger sites into a sitemap index.

## llms.txt and Markdown for AI

`llmsTxt` builds the [llms.txt](https://llmstxt.org) index: a title, a one-paragraph summary and link lists.

```ts
// src/routes/llms.txt/+server.ts
import { llmsTxt } from "@codeatlasdev/ui/seo";

export const prerender = true;

export const GET = () =>
  new Response(
    llmsTxt({
      title: "Acme",
      summary: "Invoicing for freelancers.",
      sections: [{ heading: "Docs", links: [{ title: "Quick start", href: "https://acme.com/docs/start", description: "Five minutes to the first invoice." }] }],
    }),
    { headers: { "content-type": "text/plain; charset=utf-8" } },
  );
```

`markdownNegotiation` is a SvelteKit `handle` that answers with `text/markdown` when a client sends `Accept: text/markdown` or identifies as an AI crawler (GPTBot, ClaudeBot, ChatGPT-User, PerplexityBot, Google-Extended, Applebot-Extended, ora-agent, DeepSeekBot). You decide which pages have a Markdown twin; everything else falls through to HTML. API, OAuth and `.well-known` paths are never negotiated.

```ts
// src/hooks.server.ts
import { sequence } from "@sveltejs/kit/hooks";
import { caThemeHandle } from "@codeatlasdev/ui/kit";
import { markdownNegotiation } from "@codeatlasdev/ui/seo";
import { markdownPages } from "$lib/markdown"; // Record<pathname, string>

export const handle = sequence(
  markdownNegotiation({ markdown: (pathname) => markdownPages[pathname] }),
  caThemeHandle({ defaultPreset: "ocean" }),
);
```

Responses carry `Vary: Accept, Accept-Encoding, User-Agent`, so a CDN keeps the HTML and Markdown variants apart.

## Social images

`ogImageRoute` renders an HTML template at 1200x630 through a headless browser and caches the result. HTML and CSS are the template language, so fonts, gradients and `<img>` work as in any page. The browser is passed in, so the package depends on neither Playwright nor Puppeteer: install `playwright` yourself and keep one browser alive per process.

```ts
// src/routes/og/[slug].jpg/+server.ts
import { ogImageRoute } from "@codeatlasdev/ui/seo";
import { chromium, type Browser } from "playwright";
import { posts } from "$lib/posts";

let browser: Promise<Browser> | undefined;

export const GET = ogImageRoute({
  browser: () => (browser ??= chromium.launch()),
  render: ({ params }) => {
    const post = posts[params.slug];
    return post && `<html><body style="margin:0;font:700 64px system-ui;padding:80px">${post.title}</body></html>`;
  },
  cacheKey: ({ params }) => params.slug,
});
```

Unknown slugs answer `404` without starting a browser. Renders run two at a time by default (`concurrency`) and the last 100 images stay in memory (`cacheSize`). Escape any user-provided text before putting it in the template, and inline remote images as `data:` URLs so rendering needs no network.

<Callout type="caution" title="Needs a Chromium on the server">
  Browser rendering suits Node servers and containers. On serverless or edge targets with no Chromium, generate images at build time instead, or render in a separate service and point `og.image` at it.
</Callout>

## Brand assets

A favicon, a home-screen icon and a social card are three renderings of one thing: the mark. Drawing them by hand means the brand moves and the tab icon stays behind. `@codeatlasdev/ui/vite` renders them all from one SVG and your theme, with content-hashed names.

Write the mark once, with `{{ink}}` (outline) and `{{spark}}` (accent) in place of colors. A literal color in the mark is an error.

```svg
<!-- src/brand/mark.svg -->
<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 32 32">
  <path d="M6 5h20v22H6z" fill="none" stroke="{{ink}}" stroke-width="2" />
  <path d="M16 9l2 5 5 2-5 2-2 5-2-5-5-2 5-2z" fill="{{spark}}" />
</svg>
```

Register the plugin next to `caThemePlugin`, with the same theme object:

```ts
// vite.config.ts
import { sveltekit } from "@sveltejs/kit/vite";
import { caBrandPlugin, caThemePlugin } from "@codeatlasdev/ui/vite";
import { defineConfig } from "vite";
import { theme } from "./src/lib/theme.ts";

export default defineConfig({
  plugins: [
    sveltekit(),
    caThemePlugin(theme),
    caBrandPlugin({ theme, name: "Acme", outDir: "static/brand" }),
  ],
});
```

At build start it writes `favicon.<hash>.svg` (follows `prefers-color-scheme`), `favicon.<hash>.ico` (16, 32, 48), `favicon-32`, `apple-touch-icon` (180, opaque), `icon-192`, `icon-512`, `maskable-512` and `manifest.<hash>.webmanifest`, then `src/generated/brand.ts` with their URLs. `outDir` is emptied first. Colors are `--ca-text-primary`, `--ca-brand-main` and `--ca-surface-base` of the theme's default preset, converted to `#rrggbb`. Add `static/brand/` and `src/generated/` to `.gitignore`: nothing it writes is meant to be committed.

| `caBrandPlugin` option | Default | Description |
|---|---|---|
| `mark` | `"src/brand/mark.svg"` | Path of the mark SVG, relative to the project root. The plugin warns and does nothing when it is missing. |
| `theme` | `{}` | The same `ThemeOptions` you pass to `caThemePlugin`. |
| `outDir` | `"static/brand"` | Directory served as `/brand`. Use `"public/brand"` with plain Vite and Astro. |
| `base` | `"/brand"` | URL prefix of `outDir`. |
| `manifestFile` | `"src/generated/brand.ts"` | Where the asset URLs are written, as a module exporting `brand`. |
| `name`, `shortName` | none | Fields of the generated web app manifest. |

`@resvg/resvg-js` and `png-to-ico` are optional peer dependencies. Install them where you register the plugin:

```sh
bun add -d @resvg/resvg-js png-to-ico
```

Outside Vite (an Astro prebuild script, a CI step), call `generateBrand({ mark, theme, outDir })`, which the plugin wraps. It returns the same URLs.

The hash covers the inputs (mark, resolved colors, sizes), not the rendered bytes, so it is the same on every machine. A changed color renames every file, which makes `/brand/*` safe to serve with `Cache-Control: public, max-age=31536000, immutable`; no `?v=` query is needed and scrapers see a new URL.

Link the icons with `iconLinks`, and keep the logo in the page on the same file by importing it with `?raw` and replacing the placeholders with `var(--ca-text-primary)` and `var(--ca-brand-main)`:

```svelte
<script>
  import { iconLinks } from "@codeatlasdev/ui/seo";
  import { brand } from "../generated/brand";
</script>

<svelte:head>{@html iconLinks(brand)}</svelte:head>
```

`iconLinks` emits the SVG icon, the ICO fallback, `apple-touch-icon` and the manifest link; it skips what you leave out.

### One card per page

`ogCard` returns the complete 1200x630 HTML for a social card: mark, site name, an optional eyebrow, title and description, in literal colors from `resolveBrand(theme)`. Pair it with `renderOgImage` at build time, or with `ogImageRoute` on a server. Name each card after a hash of what it shows (title, description, template version) and write that URL in `og:image` and `twitter:image`.

```ts
import { ogCard, renderOgImage } from "@codeatlasdev/ui/seo";
import { renderMark, resolveBrand } from "@codeatlasdev/ui/vite";

const colors = resolveBrand(theme).dark;
const html = ogCard({
  title: "Button",
  description: "Five variants, three sizes.",
  eyebrow: "Documentation",
  siteName: "Acme",
  mark: renderMark(markSource, colors),
  colors,
});
const png = await renderOgImage(browser, html, { format: "png" });
```

`@codeatlasdev/ui/vite` re-exports `ogCard`, `renderOgImage` and `OG_SIZE` for build scripts: Node cannot load the `seo` entry because it also exports the `Seo` component. This site does exactly that: `site/scripts/og-integration.ts` renders every page's card after `astro build`, and `site/tests/brand.spec.ts` fails when a page has no card of its own, when the favicon colors differ from the theme, or when `/brand/*` is not immutable.

## Checklist

| Check | Where |
|---|---|
| `<html lang>` set | `app.html` |
| Viewport has `viewport-fit=cover` | `app.html`, see [Mobile](/docs/getting-started/mobile/) |
| One `canonical` per indexable page, absolute | `Seo` |
| `noindex` on private routes | `Seo` |
| `sitemap.xml`, `robots.txt` and `llms.txt` prerendered | `+server.ts` routes |
| Social image 1200x630 with `imageAlt`, one per page | `ogCard` + `renderOgImage` or `ogImageRoute` |
| Favicon, `apple-touch-icon` (180) and manifest icons from one mark | `caBrandPlugin` |
