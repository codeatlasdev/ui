Every visible string the package generates (aria-labels, placeholders, empty states, "Copy", "On this page", toast and dialog buttons) comes from a message catalog. The default language is **English**; Brazilian Portuguese ships built in and any other language can be registered. There are two ways to choose the language.

The catalog holds the **library's** strings only. The text your app writes (page titles, button labels, form copy) belongs in a typed `src/lib/messages.ts`, not in templates: see [App copy](/docs/getting-started/app-copy/), which also covers the `i18n-literal` rule of `codeatlas-ui lint`.

## SSR apps: `I18nProvider`

On the server, wrap the tree in `I18nProvider`. The locale lives in Svelte context, so each request renders in its own language and concurrent requests never share state:

```svelte
<!-- src/routes/+layout.svelte -->
<script>
  import { I18nProvider } from "@codeatlasdev/ui";
  let { data, children } = $props();
</script>

<I18nProvider locale={data.locale}>
  {@render children()}
</I18nProvider>
```

`locale` is reactive: change the prop and every component inside re-renders. Pass `messages` to override phrases for that subtree (see below).

## Client-only apps: `setLocale`

SPAs and Astro islands have no per-request concern, so one module-level locale shared by every island is enough:

```svelte
<script>
  import { setLocale } from "@codeatlasdev/ui";

  setLocale("pt-BR");
</script>
```

<Callout type="warning">
  On the server `setLocale` does nothing (and warns in dev), because module state would be shared by every concurrent request. Use `I18nProvider` in SSR layouts. An `I18nProvider` always wins over `setLocale`.
</Callout>

## Add a language

Locales are any BCP 47 tag. Register a dictionary once, at module load. You only translate the keys you need; the rest fall back to English:

```ts
// src/lib/i18n.ts
import { registerLocale } from "@codeatlasdev/ui";

registerLocale("es", {
  common: { close: "Cerrar", back: "Atrás" },
  docs: { toc: "En esta página" },
});
```

Then use it with `<I18nProvider locale="es">` or `setLocale("es")`. Region tags resolve to the base language (`es-MX` uses `es`), and unknown tags fall back to English. The exported `Messages` type describes the full shape and `MessagesOverride` the partial one.

## Override phrases

`I18nProvider`'s `messages` prop and `setLocale`'s second argument are a deep partial of the catalog, merged over the chosen locale:

```svelte
<I18nProvider locale="en" messages={{ docs: { toc: "In this article" }, common: { copy: "Copy link" } }}>
  {@render children()}
</I18nProvider>
```

A later `setLocale` call replaces the previous overrides. Message functions (strings with runtime values) keep their signature:

```ts
setLocale("en", {
  notificationBell: { label: (unread) => `${unread} new in inbox` },
});
```

## Explicit props win

A text prop always beats the catalog. Components that take text (`label`, `placeholder`, `confirmLabel`, `emptyText`, ...) fall back to the catalog only when the prop is omitted:

```svelte
<TableOfContents {headings} label="Neste artigo" />
```

## Reactive locale

With `setLocale`, the locale is shared module state, so every component and every island on the page re-renders when it changes. Read it with `locale.value`:

```svelte
<script>
  import { locale, setLocale } from "@codeatlasdev/ui";
</script>

<button onclick={() => setLocale(locale.value === "en" ? "pt-BR" : "en")}>
  {locale.value}
</button>
```

Inside an `I18nProvider`, read the active locale and messages from context with `useLocale()` and `useT()`, called at the top level of a component `<script>`:

```svelte
<script>
  import { useLocale, useT } from "@codeatlasdev/ui";
  const locale = useLocale();
  const t = useT();
</script>

<p lang={locale()}>{t().common.close}</p>
```

<Callout type="note">
  With Astro, each island is a separate Svelte app but they share the module, so one `setLocale` call in the first island that runs is enough. Call it before the islands that render text.
</Callout>

## Catalog

The catalog is grouped by component, for example `docs.search.placeholder`, `dialog.close`, `pagination.next`, `fileUpload`, `dataTable` and `toast`. Each group is its own module with its English source and its `pt-BR` translation (a missing key is a type error, and a test checks that both locales have identical keys). A component bundles only its own groups, so importing `Button` does not ship the strings of `CommandPalette` or `AppShell`. `useT()` and `getMessages()` return the full catalog and bundle all of it; use them only when you need strings outside a component.

## Server errors

`createErrorHandler` never reads global locale state. Give it the language of the fallback message, fixed or per request:

```ts
// src/hooks.server.ts
import { createErrorHandler } from "@codeatlasdev/ui/kit";

export const handleError = createErrorHandler({ locale: (event) => event.locals.locale as string });
```

## Dates, numbers and masks are separate

The UI language does not change date or number formatting. Pass `locale` to the components that format values, for example `DatePicker`, which defaults to `pt-BR`:

```svelte
<DatePicker locale="en-US" label="Start date" />
```

Formatting helpers such as `formatCurrency`, `formatDate` and `formatNumber` take their own locale too.

### Formatters for pt-BR

`@codeatlasdev/ui/utils/format` (also exported from the package root) formats the values a Brazilian app shows most. Each function takes the locale as an option, defaults to `pt-BR`, and returns `"—"` for a missing value (`null`, `undefined`, `NaN`, an invalid date, a blank name); pass `empty` to write something else. The subpath has no Svelte code, so a server route, a worker or an email template can import it alone.

```ts
import {
  formatBytes,
  formatDateInZone,
  formatDateTimeInZone,
  formatMoneyAxis,
  formatMoneyCompact,
  formatName,
  formatPercent,
  formatRelativeTimeShort,
  getInitials,
} from "@codeatlasdev/ui/utils/format";

formatMoneyCompact(150000); // "R$ 1,5 mil" (cents in, no-break spaces kept)
formatMoneyCompact(95000); // "R$ 950,00": exact below a thousand
formatMoneyAxis(125000); // "R$ 1,25 mil": a chart tick, never ",00"
formatPercent(0.125); // "12,5%"
formatPercent(0.125, { signDisplay: "exceptZero" }); // "+12,5%"
formatDateInZone("2026-03-15T02:00:00Z"); // "14/03/2026": 23:00 the day before in São Paulo
formatDateTimeInZone("2026-03-15T02:00:00Z"); // "14/03/2026, 23:00"
const now = Date.parse("2026-01-01T12:00:00Z");
formatRelativeTimeShort("2026-01-01T11:55:00Z", { now }); // "há 5 min." ("ontem", "em 2 h")
formatBytes(1536); // "1,5 KB"
formatName("  maria DA silva"); // "Maria da Silva"
getInitials("Maria da Silva"); // "MS"
formatMoneyCompact(null); // "—"
```

- **Money** takes an integer in the currency's minor unit, like `MoneyInput` and `centsToDisplay`, with `currency` (default `"BRL"`) and `locale`. `formatMoneyCompact` is for a figure people read: one decimal at most, and below the locale's first abbreviation (a thousand in pt-BR, a million in de-DE) the exact amount with cents. `formatMoneyAxis` is for chart ticks: abbreviated at every size, up to two decimals, no trailing zeros.
- **Percent** takes a ratio, as `Intl` does (`0.125` is 12,5%), with `maximumFractionDigits` (default 1) and `signDisplay`.
- **Dates** are read in a fixed zone, `timeZone` (default `"America/Sao_Paulo"`), not in the zone of the server or the viewer, so the server render and every browser show the same day. A `YYYY-MM-DD` string is already a calendar day (a due date) and is never shifted. `dateStyle` and `timeStyle` take the `Intl.DateTimeFormat` values.
- **Relative time** uses the abbreviated words of `Intl.RelativeTimeFormat` (`style: "short"`, or `"narrow"`). Pass `now` when the text is rendered on the server, so the client hydrates the same string.
- **Bytes** step by 1024 with the units B, KB, MB, GB, TB and PB; `maximumFractionDigits` defaults to 1, and a value that would round to 1024 moves up a unit.
- **Names**: `formatName` writes a name in title case with single spaces, keeps `da`, `das`, `de`, `do`, `dos` and `e` in lowercase after the first word (`particles` replaces the list) and keeps a word typed in mixed case (`DiCaprio`) as typed. `getInitials` takes the first and last words that are not particles; `Avatar` derives its own initials from `alt`.

### Copy, plurals, phones, companies and months

The same subpath fills message templates, picks the plural of a word and writes Brazilian phones, company names and month labels:

```ts
import {
  formatCompanyName,
  formatCopy,
  formatPhone,
  monthLabels,
  phoneDigits,
  plural,
} from "@codeatlasdev/ui/utils/format";

formatCopy("Olá {nome}", { nome: "Ana" }); // "Olá Ana"
formatCopy("Olá {nome}", {}); // "Olá {nome}": a missing value stays visible
plural(1, "item", "itens"); // "1 item"
plural(1000, "item", "itens"); // "1.000 itens"
plural(0, "item", "itens"); // "0 item": pt counts 0 and 1,5 as singular
formatPhone("+5511987654321"); // "(11) 98765-4321"
phoneDigits("(11) 3456-7890"); // "1134567890"
formatCompanyName("  acme   comércio ltda - me"); // "acme comércio Ltda. - ME"
monthLabels(); // ["Janeiro", "Fevereiro", …, "Dezembro"]
monthLabels("pt-BR", "short"); // ["Jan.", "Fev.", …, "Dez."]
```

- **`formatCopy(template, values)`** replaces each `{key}` in one pass. A key that is absent, `null` or `undefined` stays in the text as `{key}`, so a missing value shows on the page instead of `"Olá undefined"`. Values are inserted with `String()`: format a number first with `plural` or `formatNumber`.
- **`plural(count, one, many, locale = "pt-BR")`** asks `Intl.PluralRules` for the category and writes the count with `Intl.NumberFormat` in the same locale. The `one` category takes `one`, every other category takes `many`. Portuguese follows CLDR, where `one` is any count whose integer part is 0 or 1: `plural(0, "item", "itens")` is `"0 item"`, so write your own text for zero (`"Nenhum item"`) when you want one. In English `plural(0, "item", "items", "en")` is `"0 items"`.
- **Phones** accept E.164 (`+5511987654321`), bare digits or masked text. `phoneDigits` returns the national number (area code first, 10 or 11 digits), dropping the country code `55` and a trunk `0`; it returns `""` when the text is not a whole Brazilian number (another country, a partial number, a 9-digit number that does not start with 9), and `` `+55${phoneDigits(text)}` `` is its E.164. A number in area code 55 keeps it. `formatPhone` applies the mask of `PhoneField` (`maskPhoneBR` from `@codeatlasdev/ui/forms`) and shows any other text as given, trimmed.
- **`formatCompanyName`** trims, collapses spaces and writes the legal-form suffixes at the end of the name one way: `ltda` is `Ltda.`; `sa`, `s.a`, `s/a` and `S. A.` are `S.A.`; `me`, `epp`, `eireli` and `slu` are in capitals. It never changes the case of the rest of the name, keeps the separators between suffixes (`Ltda. - ME`, `Ltda.-ME`), and leaves a suffix-like word alone when it is the first word or joined to a word by a bare hyphen (`Encontre-me`).
- **`monthLabels(locale = "pt-BR", style = "long")`** returns the 12 Gregorian month names from `Intl.DateTimeFormat` in the standalone form (Russian `Январь`, not `января`), `"long"` or `"short"`. They are labels for a select, a chart axis or a column, so the first letter is capitalised in the locale, as `MonthPicker` shows them; the rest is what `Intl` returns (pt-BR short names keep their period). Inside a sentence pt-BR writes months in lowercase: use `formatDate` there.

## In tests

The default is English. In browser tests, call `setLocale("pt-BR")` where a test asserts Portuguese text and reset with `setLocale("en")` in `afterEach`, so the module state does not leak between tests. In server-render tests, wrap the component in `I18nProvider` instead.
