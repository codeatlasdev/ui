```svelte
<script>
  import { Tabs, TabsList, TabsTrigger, TabsContent } from "@codeatlasdev/ui";
</script>

<Tabs value="overview">
  <TabsList>
    <TabsTrigger value="overview">Overview</TabsTrigger>
    <TabsTrigger value="props">Props</TabsTrigger>
  </TabsList>
  <TabsContent value="overview">...</TabsContent>
  <TabsContent value="props">...</TabsContent>
</Tabs>
```

Arrow keys move between tabs, Home and End jump to the first and last, and focusing a tab selects it (automatic activation). Disabled tabs are skipped. The panels use the `tabpanel` role and are focusable. Each `TabsTrigger` and `TabsContent` pair must share a `value`. `Tabs` is horizontal only.

`TabsList` keeps the width of its tabs (it never stretches across the column) and, when the tabs do not fit, scrolls sideways on its own with the scrollbar hidden. The selected tab is scrolled into view on mount and whenever it changes. The leading `icon` snippet and brand logos are covered on the [Dropdown Menu](/docs/navigation/menu/) page too (same `icon` / `brandIcon` pair). Add `fade` to mask the edge that still has tabs to reveal. No wrapper element or CSS is needed for 7 tabs on a phone.

`variant="line"` drops the pill list: bare text tabs with a hairline under the strip and a 2px underline on the active tab, the usual look in a page header. Add `fill` for a strip that spans the column: the list stretches to its container and the hairline closes the row (the active underline is unchanged); without it the list hugs its tabs. The trigger reads five tokens, set on the `Tabs` root or any ancestor and defaulting to the values below: `--ca-tabs-trigger-height` (`--ca-control-height-sm`), `--ca-tabs-trigger-padding-x` (`--ca-space-3-5`), `--ca-tabs-trigger-radius` (`--ca-radius-pill`, `--ca-radius-sm` for `line`), `--ca-tabs-trigger-font-size` (`--ca-font-size-body2`) and `--ca-tabs-trigger-line-height` (inherited). Setting them changes the tabs only, not the other small controls that share `--ca-control-height-sm`. Tabs that only switch a view (no `TabsContent`) are fine: a trigger points `aria-controls` at its panel only while a `TabsContent` with the same `value` is mounted, so nothing references a missing element. Name the strip with `aria-label` (or `aria-labelledby`) on `TabsList`; `TabsList` and `TabsTrigger` forward any other attribute (`data-*`, `id`, `aria-*`, event handlers) to their element.

`TabsTrigger` forwards any other button attribute (`data-testid`, `id`, `aria-*`, `onclick`, `onfocus`) to its `<button role="tab">`, and `TabsList` forwards `data-*`, `id` and `aria-*` to the `role="tablist"` element. `role`, `type` and the roving `tabindex` stay owned by the component.

## Unsaved changes in a tab

A panel unmounts when its tab is left, so a draft in it is lost. `onbeforechange` runs before the switch: return `false` to stay, or a promise that resolves once the user answers an `AlertDialog` ("Discard changes?"). Pair it with `activation="manual"`: with the default automatic activation, the focus the dialog returns to the clicked tab selects it again and reopens the dialog.

```svelte
<Tabs bind:value={tab} activation="manual" onbeforechange={(next) => (dirty ? confirmDiscard() : true)}>
```
