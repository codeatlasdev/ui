```svelte
<script>
  import { Popover, Button } from "@codeatlasdev/ui";
</script>

<Popover side="bottom" align="start">
  {#snippet triggerChild(props)}<Button {...props}>Open</Button>{/snippet}
  Popover content
</Popover>
```

Escape closes the popover and returns focus to the trigger, and a press outside dismisses it. It is a popover layer in the browser top layer, positioned with CSS anchor positioning where supported, so it stays above a dialog it opens from. Pass an interactive trigger through `triggerChild` and spread the received `props` on it; use `trigger` only for non-interactive content. For a hint that appears on hover, use [Tooltip](/docs/display/tooltip/) instead.

To control it, `bind:open` reads and sets the open state, and `onOpenChange` fires when the user opens or closes it (not when your code sets the value). The `children` snippet receives `close`, which closes the popover and returns focus to the trigger: call it after a choice is made inside, the way [DropdownMenu](/docs/navigation/menu/) closes on selection.

```svelte
<Popover bind:open>
  {#snippet triggerChild(props)}<Button {...props}>Pick a date</Button>{/snippet}
  {#snippet children({ close })}
    <Calendar onchange={() => close()} />
  {/snippet}
</Popover>
```

A `Popover` panel lives in the top layer, so it is not clipped or re-anchored by its ancestors. A hand-made `position: fixed` menu is different: it is placed against the nearest ancestor that has a `backdrop-filter`, `filter`, `transform`, `perspective`, `will-change: transform` or `contain: layout|paint`, so inside a glass header it collapses to the header box. Keep overlays out of such ancestors: use `Popover`, `Sheet` or `Drawer`, or give the header's glass to a `::before` layer (`data-ca-blur-layer`, see [GlassAppBar](/docs/navigation/app-bar/)).

A popover that holds a short action menu wants less padding than one that holds a form. `density="compact"` sets 8px padding (`--ca-space-2`) instead of 16px. To change the padding, radius, maximum width or fill of every popover, set the theme keys `components.popover` (`padding`, `radius`, `maxWidth`, `bg`), which emit `--ca-popover-padding`, `--ca-popover-radius`, `--ca-popover-max-width` and `--ca-popover-bg`; with none set the panel is unchanged (16px padding, `--ca-radius-lg`, 320px, the overlay fill). A padding token wins over `density`, and the `bg` token is a solid fill: reduced transparency still uses the solid tint.

```ts
defineTheme({ components: { popover: { padding: "var(--ca-space-2)" } } });
```

## Animating your own popover or dialog

`Popover`, `Dialog` and `Sheet` already handle their own entrance and exit. If you write a native `[popover]` or `<dialog>` yourself and animate its exit with `display … allow-discrete`, put its layout on the element's base rule, never on `:popover-open` or `[open]`. During the exit transition the element is already closed, so a layout declared only for the open state is dropped first: a grid falls back to `display: block` and the content rearranges for the length of the fade, before it disappears.

```css
.card-popover {
  display: grid; /* layout in the base rule: it holds while the exit plays */
  grid-template-columns: 64px 1fr;
  gap: var(--ca-space-3);
  opacity: 1;
  scale: 1;
  transition: opacity var(--ca-duration-base), scale var(--ca-duration-base),
    display var(--ca-duration-base) allow-discrete, overlay var(--ca-duration-base) allow-discrete;
}
.card-popover:not(:popover-open) { display: none; opacity: 0; scale: 0.96; }
@starting-style { .card-popover:popover-open { opacity: 0; scale: 0.96; } }
@media (prefers-reduced-motion: reduce) { .card-popover { transition: none; } }
```

Animate only `opacity` and `scale` (plus `display` and `overlay` as discrete), so nothing reflows while it plays. For a `<dialog>`, write the same rules with `[open]` instead of `:popover-open`.
