```svelte
<script>
  import { HoverCard } from "@codeatlasdev/ui";
</script>

<HoverCard>
  {#snippet triggerChild(props)}<a href="/people/ada" {...props}>@ada</a>{/snippet}
  <strong>Ada Lovelace</strong>
  <p>Platform engineer.</p>
</HoverCard>
```

The card previews more about its trigger (a person, a link target, a record). The trigger stays the primary action: it is a real link or button that works without the card. The card opens when the pointer rests on the trigger for `openDelay` (700 ms) and when the trigger receives keyboard focus, at once. It stays open while the pointer crosses into it and closes `closeDelay` (300 ms) after the pointer or focus leaves, on Escape, and on blur. The trigger gets `aria-describedby` pointing at the card while it is open. Tab from the trigger moves into the card, so a link inside it is reachable from the keyboard; Escape inside the card closes it and returns focus to the trigger.

It is a hint layer: it never takes Escape or outside presses from a dialog or menu underneath. The card is a popover element in the browser top layer, positioned with CSS anchor positioning where supported.

**Touch has no hover.** A tap never opens the card; it only performs the trigger's own action (follow the link, press the button), and the same information must be reachable from there. When the preview itself must be reachable on touch, use [Popover](/docs/navigation/popover/) (opens on tap) instead. Do not put content in a hover card that exists nowhere else, and do not use it for a text-only label: that is [Tooltip](/docs/display/tooltip/).

Pass an interactive trigger (a link, `Button`, `IconButton`) through `triggerChild` and spread the received `props` on it; `trigger` wraps non-interactive content in its own button. `bind:open` controls it from code, and `onOpenChange` fires for user-driven changes only.
