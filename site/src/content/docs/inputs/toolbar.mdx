```svelte
<script>
  import { Button, Select, TextField, Toolbar } from "@codeatlasdev/ui";
</script>

<Toolbar aria-label="Filter deals">
  <TextField label="Search" hideLabel width="14rem" />
  <Select label="Status" hideLabel width="10rem" options={[{ value: "open", label: "Open" }]} />
  <span class="ca-toolbar-spacer"></span>
  <Button variant="outlined" tone="neutral">Export</Button>
</Toolbar>
```

`Toolbar` is `role="toolbar"` with a flex row that wraps and a `--ca-toolbar-gap` (default `--ca-space-2`). It sets `--ca-field-width: auto` for everything inside, so a `TextField`, `Select`, `Combobox`, `NumberField`, `ColorField` or a date field takes the width its content needs; give one a size with its `width` prop (`"10rem"`, `"fit"`) and let `ca-toolbar-spacer` push what follows to the end. A field that must still fill the row says `width="full"`. Give it an `aria-label`: a dev warning fires without one. There is no separate `FilterBar`: this is it.

Fields in a toolbar usually do not need their label drawn: pass `hideLabel` and the name stays for assistive tech. A `Select` whose value is cut by its width shows the full text in a `title`.

## When the row is too narrow

By default the row wraps, so on a phone a composer bar takes two or three lines and can push its primary action out of view. Pick a strategy with `overflow`:

- `"scroll"`: one line, scrolls sideways, no scrollbar drawn, items keep their size. Use it when every option must stay reachable, such as a strip of quick filters.
- `"menu"`: one line. The items that do not fit move, in order, into a `DropdownMenu` behind a More `IconButton` at the end (`aria-label` is the localized "More", `moreLabel` overrides it). The row is measured with a `ResizeObserver` and again on resize and when fonts load, so items come back when there is room. The items stay in the DOM: picking a menu entry clicks the real item, so its handler runs. The trailing items move first; the leading ones stay.

In `menu` mode a direct child moves only when a menu entry can act for it: a `button` or `a[href]` (an `IconButton`, a `Button`), or any child you mark with `data-overflow="Label"` that holds one (a `<span data-overflow="Export"><Button>…</Button></span>`; the entry clicks the button inside). Everything else stays in the row so no control becomes unreachable: a `ButtonGroup`, a `TextField` or `Select`, a spacer. Put `data-priority="primary"` on the action that must never leave the row (the send button); `data-overflow="Label"` also names the entry when it needs a different name than the item's `aria-label` or text. A disabled item becomes a disabled entry. Items added or removed after mount are measured too. A `ca-toolbar-spacer` keeps pushing what follows to the end.

A `ButtonGroup` inside a toolbar can shrink (`min-width: 0`). It takes no `overflow` prop on purpose: its members are joined by one shared seam and radius, so splitting them across the row and a menu would break the group; in a `menu` toolbar it stays in the row. In `scroll` mode the row keeps a focus-ring margin around the items, so rings are not clipped.

## Field width

Every field takes `width?: "full" | "auto" | "fit" | string` (default `"full"`, the row): `auto` and `fit` size to the content, a CSS length sets the width. It is written to `--ca-field-width`; `--ca-field-min-width` sets a floor (default `0`). `NumberField` also takes `steppers?: boolean` (default `true`): `false` drops the +/- buttons for a compact numeric input.
