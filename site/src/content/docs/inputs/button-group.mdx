```svelte
<script>
  import { Button, ButtonGroup } from "@codeatlasdev/ui";
</script>

<ButtonGroup aria-label="View range">
  <Button variant="outlined" tone="neutral">Day</Button>
  <Button variant="outlined" tone="neutral">Week</Button>
</ButtonGroup>
```

`ButtonGroup` is `role="group"`: give it an `aria-label` (or `aria-labelledby`) so a screen reader announces what the buttons share; a dev warning fires without one. It only changes how the buttons sit: each keeps its own variant, size, `onclick`, loading and disabled state, and its own Tab stop (Tab moves through the group, there is no roving focus). The inner corners are square, the outer ones keep `--ca-radius-control`, and neighbours overlap by one border so the seam is a single line. The hovered, open or keyboard-focused button is raised so its ring is never half hidden.

Members are `Button`, `IconButton` and a [`DropdownMenu`](/docs/navigation/menu/) whose `triggerChild` is one of them (the menu itself is portaled, only the trigger sits in the group): that is the split button. `orientation="vertical"` stacks them.

It is for actions. A single choice that stays selected is [`SegmentedControl`](/docs/inputs/segmented-control/); a set of toggles is [`ToggleGroup`](/docs/inputs/toggle-group/).
